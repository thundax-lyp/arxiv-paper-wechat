# arXiv Agent 与大模型研究简报｜2026-09-22｜精选

本期关注一个共同问题：智能体正在获得更长的记忆、更复杂的工具和持续自我改进能力，但可靠性不能只靠最终得分来证明。多篇工作把验证前移到训练环境、执行轨迹、证据链与更新准入环节，也有研究揭示长上下文、检索污染和人机沟通中的新失效模式。

阅读推荐：🌟 值得关注；🌟🌟 建议阅读；🌟🌟🌟 优先精读。星标表示本期阅读优先级，不代表研究结论的可靠程度。

## 智能体系统与工具使用

### 智能体自我修改必须经过外部准入控制

Self-Healing Harness for Runtime Oversight of Agent Self-Modification

🌟🌟🌟

**问题**：智能体能够修改自己的长期行为，但修复当前失败的规则可能悄悄破坏原本正常的任务。

**结论**：外部运行时门禁发现，383 个被回放裁决拒绝的修改中有 211 个修好触发问题却损害受保护案例；局部改进不足以获得持久权限。

**新意**：把自我修改视为准入控制：智能体只负责提出候选规则，独立门禁通过回放、非退化检查和全局复测决定是否持久化。

让智能体从失败中写出新规则很容易，真正困难的是判断这条规则能否留下来。论文把候选修改放在外部工作区中，先给它临时执行权，再运行“检测、提示、修复、验证”循环。能回放时，系统在同一任务和受保护案例上做配对比较；不能回放时，才退化为证据较弱的前向试验。只有触发问题改善、关键指标没有越过退化阈值，规则才获得跨回合持久权限。实验覆盖应用操作、终端任务和工具对话，最有冲击力的结果是：许多修改确实修复了当前失败，却同时破坏先前能做对的任务。如果只看触发点，这些危险修改都会被接纳。系统还观察到单条规则分别通过后，累积起来仍可能造成整体下降，因此额外加入规则集级别复测。所有修改都停留在可检查、可撤销的外部上下文中，闭源模型也能使用。

**编辑点评**：实验直接证明了局部修复与旧能力回归的冲突，但每次只抽查少量受保护案例，发现的是下界而非真实发生率。连续在线适应也没有独立训练与测试分区。

**为什么值得读**：它给自我进化智能体提供了一个务实的安全边界：提案权可以交给模型，持久权限必须由外部证据门禁掌握，而且单次准入之后还要检查规则组合。

[阅读论文 PDF](https://arxiv.org/pdf/2609.24130)

### 把优秀运行框架的行为蒸馏进模型权重

Harness-Zero: Harness Distillation via Agent-as-Harness

🌟🌟🌟

**问题**：专用运行框架能提升智能体，但最佳框架随领域、任务和模型变化，长期部署会陷入不断增长的框架路由与维护。

**结论**：用临时指导智能体把专用框架行为转成目标动作空间的示范后，学生在移除专用框架时仍将平均成功率从 23.3% 提升到 44.3%。

**新意**：不直接模仿不同动作空间的轨迹，而是让“智能体充当框架”，在执行前纠正学生提案，再把纠正后的兼容轨迹用于训练。

运行框架决定模型能看到什么、如何调用工具、何时反思，因此同一个模型换框架后能力可能大幅变化。直接蒸馏却有结构障碍：教师框架和部署框架的动作空间、状态信息并不一致，教师轨迹不能原样监督学生。论文引入一个临时的指导智能体，让学生仍在目标框架中提出动作，再由指导智能体参考优化框架的策略，在执行前纠正这些动作。这样得到的成功轨迹从一开始就兼容最终部署接口，可以用于监督微调。知识工作、工具使用和科学任务上的实验显示，学生在不携带专用框架时仍保留了大部分行为模式，平均成功率甚至略高于继续挂载原框架的结果。其含义不是框架不重要，而是框架可以成为训练期教师。当前证据覆盖三个领域，训练成本、跨模型稳定性和复杂权限边界下的安全性仍需要更多研究。

**编辑点评**：对照实验支持行为确实从框架迁入权重，而非仅靠部署时路由获得。不过任务域和模型规模有限，蒸馏后的行为是否会在新环境中产生不可见副作用尚未充分测量。

**为什么值得读**：它提出了一条减少智能体基础设施碎片化的路线：先用昂贵或复杂框架发现好行为，再把这些行为转换成统一部署框架可学习的数据。

[阅读论文 PDF](https://arxiv.org/pdf/2609.24974)

### 自动写出的论文，代码和实验真的支持它吗

Beyond the Text: Verifying That Agent-Written Papers Are Backed by Their Artifacts

🌟🌟🌟

**问题**：自动科研智能体能同时产出论文、代码和实验，但传统评审难以判断三者是否真正一致。

**结论**：静态对照与动态执行结合后，可以更有效地定位主张与仓库证据之间的不一致；它验证的是内部一致性，不是科学结论本身是否正确。

**新意**：把论文主张先编译成可执行的核查目标，再让审计智能体沿着主张、代码绑定和运行证据逐层追踪。

自动科研最危险的并不一定是明显捏造，而是论文、实现和实验在多轮修改后悄悄分叉：方法写进了文稿，却没进入代码；数字能够复现，但运行的是另一套配置。该系统先从论文中抽取方法、实现与实验主张，形成带条件的核查契约，再扫描仓库寻找对应文件、参数和调用关系。静态阶段负责判断实现是否存在、配置是否一致，动态阶段则选择可运行的目标，在隔离环境中执行并收集带来源的证据。两条证据链合并后，系统可以区分“代码里没做”“做了但配置不同”和“数字出现了却不能支持原主张”。这种设计很适合自动科研进入工程流程后的质量门禁，因为报告中的每个判断都能回溯到具体证据。当前评测来源单一，仓库缺数据、缺模型或依赖失效时，动态核查也会受阻；更重要的是，内部一致并不等于实验设计合理或结论真实。

**编辑点评**：现有证据支持它作为一致性审计工具，而不是替代同行评审。单一自动科研平台的数据分布，以及不可执行仓库带来的选择偏差，都会限制外推。

**为什么值得读**：它给出了将“论文看起来可信”改造成“主张可追踪、实现可定位、结果可执行核验”的具体工程接口，对自动科研平台和代码审稿工具都很有启发。

[阅读论文 PDF](https://arxiv.org/pdf/2609.22111)

## 多智能体与协作

### 多智能体可以学会怎样一起推理

Self-Organizing Agent Teams Learn to Reason Together

🌟🌟🌟

**问题**：当解题结构未知时，预先固定分工和路由常常不合适，团队需要从协作经验中学会如何组织推理。

**结论**：从少量协作记录中提炼的固定团队策略能迁移到未见任务，并在数学物理上超过最强成员与理想路由；前提是正确思路出现后能够被团队识别。

**新意**：学习的不是某道题的答案或分解，而是角色形成、发言阶段、质疑修复和信息汇合的可复用组织策略。

多智能体常被理解为把同一问题交给多个模型，再投票或让路由器挑答案。这篇工作问得更深：团队本身能否学习组织方式。研究者让固定成员复盘少量历史协作，抽取谁先探索、何时质疑、如何修复局部推理、怎样合并结论等策略；测试时不再为每道题重新规划，而是把同一组织策略迁移到新任务。数学与物理套件上，团队平均准确率比最强成员高近十八个百分点，也超过将成员独立答案交给完美路由器的结果，说明交流确实构造了单个成员未能独立生成的解。作者进一步发现，收益与“正确推理一旦出现是否容易识别”强相关。团队能够扩大候选解覆盖，却不总能选对最终答案，因此在知识与逻辑任务上仍有明显落差。这一关系目前是事后相关分析，不能当作因果机制。

**编辑点评**：结果支持组织策略具有迁移价值，也排除了单纯增加采样和路由选择的解释。但测试域仍以可验证推理题为主，开放任务中的协调成本和错误放大尚未覆盖。

**为什么值得读**：它提醒多智能体研究把重点从“多开几个模型”移向“让团队学习互动协议”，并给出一个判断协作是否值得的实用线索：答案出现后是否可被成员可靠识别。

[阅读论文 PDF](https://arxiv.org/pdf/2609.22682)

## 评测与安全

### 先画蓝图，再生成可验证的智能体训练环境

AutoGym: Blueprint-First Generation of Verifiable Agent Gyms

🌟🌟🌟

**问题**：强化学习需要任务、可执行环境和可靠验证器成套出现，而人工搭建昂贵、静态且容易被模型能力迅速饱和。

**结论**：先约束解空间再生成环境，可以稳定产出跨难度的可执行任务，并为训练提供明确奖励；真实接口逼真度和开放式验证仍是短板。

**新意**：把可解性和验证条件放到生成之前，用蓝图控制任务拓扑、交互深度与干扰项，再以失败分布驱动下一轮课程。

许多自动生成任务只是把题面写得更绕，真正的解法空间并没有变难，最后还要依赖另一个模型裁判。这里的关键转向是：不从自然语言题目开始，而从“什么算有效解、环境必须提供什么、验证器检查哪些状态”开始。蓝图确定后，系统再生成工具、数据与界面，并通过修复循环消除不可解或不可判定的实例。难度不再靠形容词，而由任务图结构、交互层数、能力轴和干扰组成显式控制。模型在某类参数组合上表现过好或过差时，后续生成分布会随之调整，形成主动课程。生产力和时间推理实验显示，生成任务覆盖从易到难的区间，还能针对已发现的能力缺口定向扩充。代价是环境多为模拟接口，开放式答案仍需要语义裁判；现有训练实验也只覆盖一个八十亿参数模型和有限步数。

**编辑点评**：证据较完整地支持“蓝图优于单次生成”这一构造原则，但尚不足以证明生成环境能替代真实工作系统。任务修复和语义评分中仍有模型依赖。

**为什么值得读**：它把智能体数据生成从写题器提升为环境工程：先定义状态、动作和可验证结果，再谈规模化训练。做智能体基准或强化学习平台的人可以直接借鉴这套顺序。

[阅读论文 PDF](https://arxiv.org/pdf/2609.22592)

### 自我进化不能只看最后一次得分

Beyond Endpoint Performance: Process-Level Evaluation of Self-Evolving Agents

🌟🌟🌟

**问题**：自我进化智能体会持续修改记忆和技能，终点评分无法说明能力何时出现、何时退化，以及哪次更新造成了变化。

**结论**：逐检查点测量发现，熟悉分布上的提升常在分布变化后消失，少数更新路径承载大部分遗忘，而且没有方法能可靠完成规则反转。

**新意**：固定模型和工具，只冻结并回放不同时刻的外部产物，把泛化、保持和规则修订拆成三条独立演化路径。

许多自我进化实验只比较开始与结束：最后得分更高，就宣称记忆或技能在成长。但中间可能先学会又遗忘，也可能只对相似任务过拟合。这个基准把经验流切成连续检查点，每到一个检查点就冻结当前产物，用只读方式在留出任务上复测同一能力。积累路径测新知识能否迁移到未见任务；干扰路径在学习无关内容后测旧能力是否保持；反转路径则要求智能体在新证据出现时修改旧规则。十种记忆与技能演化方法的结果并不乐观：相似条件下的增益遇到分布变化会明显衰减，遗忘往往集中在少数关键更新上，而规则适应没有形成稳定能力。更值得注意的是，搜索过程中常出现能带来显著留出收益的候选产物，但现有接受规则无法把它们从过拟合修改中挑出来，说明瓶颈不仅是生成更新，更是选择更新。

**编辑点评**：过程评测清楚揭示了终点指标遮蔽的退化，但环境主要围绕校准后的市场任务，能否迁移到代码、网页和真实组织流程还需验证。

**为什么值得读**：它给“智能体会自我改进”提供了更严格的证据结构：不仅问有没有进步，还问进步能否迁移、能否保留、能否在规则失效时主动修订。

[阅读论文 PDF](https://arxiv.org/pdf/2609.24663)
