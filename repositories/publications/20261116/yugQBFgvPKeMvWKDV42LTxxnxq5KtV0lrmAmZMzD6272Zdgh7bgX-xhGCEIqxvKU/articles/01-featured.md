# arXiv Agent 与大模型研究简报｜2026-11-16｜精选

智能体执行长任务时，真正容易丢失的往往是下一步依赖的证据。本期沿着证据的保存、委派、核验和动作放行，梳理这些环节怎样影响成功率和安全性。全览另涵盖模型训练、推理、部署及专业任务评测。

阅读推荐：🌟 值得关注；🌟🌟 建议阅读；🌟🌟🌟 优先精读。星标表示本期阅读优先级，不代表研究结论的可靠程度。

## 智能体系统与工具使用

### 长程代理既压缩状态，也要留下可追溯证据

CarryOn: Learning What to Keep in Context for Long-Horizon LLM Agents

🌟🌟🌟

**问题**：长程代理必须控制不断增长的交互历史，但摘要压缩可能抹掉之后执行工具操作所需的精确证据。

**结论**：在三个工具任务基准上，紧凑状态加来源关联证据取得75.7%的宏平均成功率，比最强基线高6.7个百分点，并在作者定义的资源指标上表现领先。

**新意**：该方法不把上下文管理简化为全文保留或摘要替代，而是同时维护可执行的压缩状态和可回溯的原始证据。

长任务代理的历史记录里，既有下一步决策真正需要的信息，也有大量已经失效的过程细节。只保留完整日志会拖长上下文、增加资源开销；只保留摘要又可能丢掉精确数值、操作结果或来源线索。该方法把这两类需求放在同一个上下文管理器中：一部分记录当前紧凑执行状态，另一部分保留细粒度且能追溯来源的证据；学习式选择器和自适应策略负责决定哪些证据继续留在上下文。作者在 三个工具任务基准 上测试，并使用三个不同执行模型。宏平均任务成功率达到75.7%，比最强基线高6.7个百分点；论文还报告了同时考虑任务成功与资源消耗的指标，以及每次成功所花费的资源，该方法在两项指标的平均结果上领先。值得关注的是，这种设计把“记住什么”与“如何证明这条信息来自哪里”联系起来，适合有多步工具调用的工作流。不过，基准成功率和定义好的资源指标无法完整代表真实部署中的存储、检索延迟与长期漂移。实际采用时仍需观察证据选择是否可靠、上下文开销是否下降，以及任务失败时能否从来源记录中追查原因。

**编辑点评**：三类任务和多个执行模型提供了较广的基准证据，但真实长期运行中的检索延迟、记忆漂移和证据覆盖率尚不能由这些结果充分回答。

**为什么值得读**：实现长程代理时，可以把压缩状态与可追溯证据分层保存，并同步测任务成功和每次成功的资源成本。

[阅读论文 PDF](https://arxiv.org/pdf/2611.17808)

### 先验证计划，再放行智能体的工具调用

Soteria: Formally Verified Planning with Runtime Enforcement for Safe LLM Agents

🌟🌟🌟

**问题**：多步工具代理遇到违规动作后，需要知道哪些步骤还能推进，以及怎样继续满足领域规则。

**结论**：在作者测量的三个基准中，系统没有违反已编码规范，合规成功率较最强基线提高4.7至43.9个百分点。

**新意**：把分层计划编译成可验证的状态转移，并将已核验的分支带到运行时，用于放行和恢复。

订票代理接到退款请求后，往往要查预订、看票价规则，再决定是否能退款。只在最后一步加拦截，可能保护资金，却留下一个不知道该继续查什么的代理。论文先让模型给出有条件分支的分层计划。子计划将业务步骤分开，工具合约规定调用前提、返回结果和状态如何变化。验证器沿可能的路径检查时间、参数传递及跨步骤约束，例如一次写入是否使用了先前查询确认的对象。

运行时，每次调用都要经过独立监控。系统把拟议调用追加到已有轨迹的末尾，检查它会不会破坏规范，再决定是否放行。工具返回后还检查结果是否符合合约。执行者看到的是随观察结果逐步收缩的工作清单，走到被拦截的分支时，就能从当前状态寻找余下可行的动作。在默认模式中，清单用于引导，监控器才是运行时放行的依据。

作者用航空预订、零售订单与工具任务中的207个用例评估四种模型，报告已编码约束零违规，合规成功率比各组最强基线高4.7至43.9个百分点。这里的安全边界由规范覆盖和工具合约决定。验证器可能受限于支持的理论和搜索预算，真实接口如果偏离合约，计划推导得到的保证也会失去前提。

**编辑点评**：最好把结果理解为所测规则和工具合约下的保护。规范由半自动流程生成并经人工核验，对其它领域的政策覆盖和接口真实性仍需验证。

**为什么值得读**：可以据此设计一个更具体的运行时验收：同时测违规是否被拦下、拦下后还能完成多少任务，以及工具返回违约时系统在哪里停止。

[阅读论文 PDF](https://arxiv.org/pdf/2611.17880)

### 智能体记忆何时该删：误删关键事实会抵消整理收益

When Should LLM Agents Forget? Memory Filtering Under Query-Critical Resolver Errors

🌟🌟🌟

**问题**：记忆清理常默认过期判断足够可靠，但一次误删可能让后续任务再也无法找回关键事实。

**结论**：硬删除在解析标签可靠时可提升答题表现，解析出错尤其误删查询关键事实时会造成明显损失；小样本冻结复现尚不能确认稳定收益。

**新意**：论文把总体解析准确率与“是否误删当前问题所需事实”区分开，并测试按部署匹配数据选择删除策略的门控。

长程代理的记忆整理看似是压缩问题，实际还包含对事实有效性的判断。若系统把旧记录标成过期并直接删除，判断正确时能减少干扰；判断错误时，丢失的证据无法再被后续推理利用。作者在记忆问答基准中比较四类组装方式：不看有效性地保留全部信息、保留但标记信息、按查询意图硬删除，以及加入预算约束的变体。实验先从金标准标签出发逐步注入随机错误，再分别考察误删和误留，避免只用一个总体准确率概括不同风险。三种模型的结果都显示，硬删除的优势会随解析可靠性下降而减弱并反转；误删当前问题所需事实尤其有害。作者进一步将问题拆成校准集和测试集，在各错误环境中预先决定是否启用硬删除，测试表现优于始终采用单一策略。不过，这仍是单个基准上的回顾式门控结果。冻结提示、问题去重的百题复现中，硬删相对直接保留仅高三个百分点，区间跨过零；解析错误的注入方式也不一定符合真实系统。更稳妥的实践结论是把删除当成有代价的决策，并在匹配部署的数据上专门测关键事实误删风险。

**编辑点评**：实验细致地区分了误删、误留和提示冻结后的复现，但错误注入与记忆问答基准限制了外推；文中诊断出的准确率交叉点不是可直接套用的部署阈值。

**为什么值得读**：做记忆压缩或过期清理时，可把关键事实误删率加入测试，并保留无标签删除策略作为对照。

[阅读论文 PDF](https://arxiv.org/pdf/2611.17338)

## 多智能体与协作

### 多智能体安全可能被委派链中较弱的一环决定

Only as Safe as the Weakest Agent: A Break That Appears Only When the System Is Multi-Agent

🌟🌟🌟

**问题**：孤立模型安全测试看不出强主代理把资料读取委派给较弱子代理后，错误如何进入最终决策。

**结论**：在构造的文件检索攻击中，委派会显著增加伪造记录导致的错误修改；风险来自信息传递和聚合链，不只来自主模型本身。

**新意**：研究直接测试未修改的编码代理及其子代理机制，把系统级委派作为安全评估对象，并追踪错误在聚合阶段的传播。

代理系统常把复杂任务拆给不同模型：主代理负责计划，子代理搜索资料或执行局部步骤。这样的分工降低成本，却也增加了信任边界。作者在本地文件库里植入伪造记录，让代理回答问题并据此修改内容。若强主代理自行搜索，千余次试验中几乎没有出现有害修改；当它把读取交给便宜的子代理后，多种系统更容易采信伪造信息。模拟实验还考察不同模型组合，并发现即使聚合器单独工作时很少出错，也可能复述被污染子代理的结论。这个结果提醒人们，系统可靠性并不等于最强模型的单体可靠性：读取来源、子代理能力、汇总规则和最终写入权限共同决定结果。实际工程上，可以对委派结果保留来源证据，让主代理在执行高影响操作前独立核验关键事实，并限制未核验内容直接触发写入。但论文采用的是本地资料库投毒任务，不能据此断言所有多代理产品都会出现同样比例的错误；攻击强度、任务形式和防护配置都会改变结果。

**编辑点评**：真实代理实验与多模型模拟强化了系统级风险的论证，但攻击集中于植入伪造本地记录的问答场景，报告比例不应被理解为一般代理任务的发生率。

**为什么值得读**：设计多代理流程时，应把来源追踪、子代理输出复核和最终操作权限作为同一条安全链评估。

[阅读论文 PDF](https://arxiv.org/pdf/2611.17520)

## 大模型训练与对齐

### 让强化学习中的智能体脚手架随训练演化

ModHarness-RL: Recasting Harnesses as Learnable and Evolving Programs for Agentic RL

🌟🌟🌟

**问题**：强化学习往往在固定脚手架下进行，但训练进行后，模型需要看的历史和需要帮助的失败类型都会改变。

**结论**：可更新脚手架在代码定位上的综合分数比固定设置相对提高19%，其它两个环境的对照主要验证了单个模块。

**新意**：把上下文压缩和偏航引导写成作用于结构化轨迹的可执行程序，用重放筛选更新。

训练编码代理时，完整的工具输出可能早早占满上下文。固定压缩策略也可能删掉真正决定文件定位的线索。另一方面，训练刚开始时反复踩的坑，有些在后续轮次会自然消失。如果提示永远按同一规则触发，模型已经会做的步骤也可能继续受到干预。论文把这两类工作写成可执行程序，程序的输入是带类型的交互状态块，输出分别是送给模型的上下文及必要的引导。

压缩程序先针对基础策略优化，候选版本要经过执行验证和留出任务比较。引导程序则随策略更新。生成程序的模型先对比同一任务中成功和失败的轨迹，提出可检测的失败模式，再把触发程序放到历轮保存的轨迹上执行。回放可以看到某种失败是否正在自然下降。长期持平或上升的模式更值得加入纠正引导，尚不明确的可以继续观察。这些回放不需要每条轨迹重新调用模型。

在完整评测的代码定位任务中，论文报告相对固定脚手架的平均分提升19%。代码定位受益更多的是引导，有限上下文下的家务任务则更受益于压缩。完整联合方案和第三方基线在代码定位上比较得最充分，其余两个环境只支持对单个模块的判断。候选更新的留出门也可能因样本少而误收略差的程序。

**编辑点评**：把程序生成、运行验证和策略训练拆开后，更新可追踪。论文仍借助专有模型写程序，较完整的基线对照集中在代码定位。

**为什么值得读**：对照组可以分别锁定上下文压缩器和干预程序，观察成功率、预填充开销及误触发是否来自不同部件。

[阅读论文 PDF](https://arxiv.org/pdf/2611.18533)

## 评测与安全

### 同一条执行轨迹，压缩后验证器还判得准吗

Do Verifier Judgments Survive Abstraction? Measuring Verification Transport for LLM Agent Evaluation

🌟🌟🌟

**问题**：委派、工具封装和历史压缩会让核验器只看到执行轨迹的一部分，同一个判断是否还能成立缺少对照。

**结论**：相较原生轨迹，封装和委派让约三成原本正确的判决失效。恢复来源证据挽回85.5%的失败，也改变了部分原先仍正确的结果。

**新意**：冻结同一条执行轨迹、结局和标签，仅改变证据的呈现与可追回程度，直接隔离表示变化。

一个支付工具可以在内部依次检查权限、核对金额、提交订单。代理的操作和结果都一样，核验器可能看到每条底层调用，也可能只看到支付工具返回的成功摘要。后者丢掉的细节，会让原先可靠的安全判决发生变化。论文把同一底层运行保存下来，分别提供原生轨迹、经过工具封装或委派或压缩的视图，以及恢复来源后的视图。任务、评分标准和核验器在配对条件内保持一致。

作者先筛出核验器在原生视图下已判对的案例，再看这些判决在表示变化后是否仍成立。汇总四项基准、七个模型和四种核验协议，封装和委派分别让31.0%和30.9%的原本正确判决失效，历史压缩为20.3%。直接给判决的协议更容易说错，要求先找证据的协议在资料减少后更常弃答。系统若只统计错判，就可能漏掉覆盖率下降。

当研究者把来源证据恢复到相应视图中，85.5%的失效判决恢复正确。补回内容也有代价，在抽象后仍判断正确的样本中，有5.2%反而退化。论文使用受控转换和恢复过程，实务中还需要知道哪些记录仍可取回，以及在时限内取证要花多少成本。

**编辑点评**：配对控制支持表示改变本身可以造成判决变化。实验构造的抽象和恢复过程只覆盖三类边界，不能据此预测任意系统的线上错误率。

**为什么值得读**：可以将同一次真实执行按原始、压缩和按需回查三种形式送给裁判，分别度量错判、弃答和恢复收益。

[阅读论文 PDF](https://arxiv.org/pdf/2611.18471)
