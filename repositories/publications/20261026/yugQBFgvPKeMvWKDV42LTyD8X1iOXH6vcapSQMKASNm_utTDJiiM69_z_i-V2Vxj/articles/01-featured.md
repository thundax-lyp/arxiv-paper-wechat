# arXiv Agent 与大模型研究简报｜2026-10-26｜精选

本期重点看智能体怎样持续省时、怎样把算力花在合适角色，以及评测为何必须同时检查过程与结果。在线工具记忆、稀疏反向训练和强化学习评论器各自给出不同的节省路径；长对话与科学任务评测则提醒我们，短期流畅和报告完整仍可能掩盖执行失败。

阅读推荐：🌟 值得关注；🌟🌟 建议阅读；🌟🌟🌟 优先精读。星标表示本期阅读优先级，不代表研究结论的可靠程度。

## 智能体系统与工具使用

### 在线工具记忆让推测调用持续受益

SPECMEM: Accelerating Agentic Tool Calling via Live Memory Management

🌟🌟🌟

**问题**：工具调用草稿库在部署后冻结，会随着用户产生新任务逐渐失去命中；提前执行还可能带来不可逆错误。

**结论**：在线写回维持了合成多会话流中的接受率，最高实测加速1.74倍；副作用拦截依赖工具安全标注。

**新意**：把调用记忆作为有写回、隔离与淘汰的长期组件管理，同时把执行资格与检索信心分开。

推测解码先拿一个廉价草稿，再由目标模型核验；草稿越接近目标输出，越能减少逐词元等待。工具调用尤其适合复用历史：同一用户常重复查询或操作，但也不断出现新参数和新任务。只在启动时构建一次记忆库，会错过这些部署后积累的可复用经验。

这项工作把每次核验通过的调用写回用户专属存储，在容量满时淘汰久未使用的条目。下次请求先检索旧调用作为草稿，目标模型继续负责接受或修正。另一个独立门控决定草稿能否提前执行：有不可逆副作用的工具必须等核验通过，不能因为检索相似度很高就放行。

在作者构造的多用户、多会话任务流中，在线记忆相对冻结记忆的平均接受词元增加27%，不同基准收益随新任务到达比例变化。计时实验给出最高1.74倍加速。消融说明接受收益主要来自持续写回；用户隔离并未提高接受率，却堵住了测到的跨用户历史泄漏。

这些是有启发的系统证据，但不是生产日志验收。用户和会话由基准合成，重复比例直接影响收益；对照系统在统一框架里重实现，计时采用外部推测循环。副作用门控还依赖正确的工具声明，因此接入实际系统时应先测真实重复率与每类工具的可提前执行条件。

**编辑点评**：记忆维护与副作用门控分别有消融支持；真实多会话遥测与引擎内部集成仍是关键缺口。

**为什么值得读**：它把性能、用户隔离和执行时机放在同一调用路径上，适合工具密集型智能体寻找可验证的加速点。

[阅读论文 PDF](https://arxiv.org/pdf/2610.31840)

### 全双工对话为何几分钟后开始崩溃

Why Full-Duplex Speech Models Collapse in Long Conversations

🌟🌟🌟

**问题**：单轮语音评测看不到全双工模型持续生成后出现的沉默、重复和乱码。

**结论**：固定缓存初始化锚点并惩罚近期重复，在两种滑窗模型中显著减少崩溃，但仍有残余沉默和额外耗时。

**新意**：把长时故障分解为缓存锚点驱逐和输出自强化，并用无需重训的干预测试因果诊断。

全双工模型听别人说话时也在按音频帧持续生成状态，因此上下文消耗速度与普通文本聊天不同。短对话正常，并不意味着模型能够稳定工作半小时。论文先用长对话回放和会响应模型的伙伴两种设置，检查五个模型的持续运行表现，发现它们最终都退化或到达容量上限。

对滑动窗口模型，研究定位了两个互补机制。窗口把最早的缓存条目驱逐后，模型进入不同于初始化阶段的状态，沉默和乱码随之增加；近期自己说过的话又会强化后续重复。作者分别固定首个初始化锚点，及在文本输出上施加兼顾沉默的重复惩罚，再通过单独和联合干预核对解释。

一小时回放中，一种模型的重复、持续沉默和乱码从65%、100%、100%降到0%、7.5%、0%；另一种模型仍有47.5%达到沉默定义，虽然其中多数很快恢复。自适应模型伙伴实验中，联合修复把各类故障都压到不超过10%的会话。故障率下降不等于对话内容自动正确，论文还用模型评分检查连贯与回应性。

修复无需重训，也不增加缓存容量，却有计算代价：单卡计时中固定锚点增加约24%开销，联合方法仍能实时运行。证据说明初始化状态管理值得排查，但修复只覆盖两种滑窗模型，不能当作所有全双工架构的通用解决方案。

**编辑点评**：故障干预与消融支持机制解释；部分内容质量依赖模型评分，持续沉默仍未完全解决。

**为什么值得读**：适合做实时语音助手的读者，把几十分钟连续运行、缓存驱逐点和恢复行为纳入验收比只测首轮时延更有用。

[阅读论文 PDF](https://arxiv.org/pdf/2610.32349)

## 多智能体与协作

### 多智能体应联合选择提示与执行模型

Not Every Agent Needs the Strongest Model: Unified Prompt-Model Optimization for Heterogeneous LLM-based Multi-Agent Systems

🌟🌟🌟

**问题**：多智能体每个角色都使用最强模型，可能把大量成本花在不需要的能力上；只改提示又无法改变这种分配。

**结论**：在五个基准的集中式设置中，联合选择平均分略升，加权部署成本下降85.2%，但这是一组价格与模型配置下的结果。

**新意**：把角色提示与执行模型放进同一个搜索空间，并用协作依赖检查局部改动是否破坏下游。

多智能体的费用不只由调用次数决定，也由每个角色使用什么模型、输出如何影响后续步骤决定。一个承担简单归纳的角色与一个负责关键推理的角色，未必需要同等昂贵的模型。如果把模型分配固定，提示优化即使有效，也可能一直在不合适的成本结构里搜索。

这项工作先从执行轨迹提出提示与模型的候选组合，再分别观察该角色、本角色下游以及整个系统的表现。质量与费用共同决定保留哪些配置；随后按照角色依赖协调更新，避免单个角色变好却让其他角色失去可用输入。历史轨迹被保存为成功和失败经验，供后续轮次检索。

作者在五种任务和五种执行结构中比较该方法。集中式主比较的平均成绩从69.79到70.40，变化主要体现为维持质量时大幅降低加权部署费用，而不是能力的大幅跃升。三轮搜索中，每任务只使用50例优化池，最终配置再进入完整评测。

阅读时必须区分部署费用、搜索阶段费用和实际延迟。论文还报告优化费用下降，但双方采用的优化器与协调模型不同，价格差本身贡献很大。因此可迁移的启发是同时搜索提示与模型分工，而不是把85.2%直接当作任何系统的节省预期。

**编辑点评**：基准与结构覆盖较广，但成本是按词元及模型价格加权的；采用不同优化模型也使算法与价格贡献难以完全分开。

**为什么值得读**：适合维护多角色流程的读者：可把关键角色的正确率、下游失败和实际账单一起作为配置搜索目标。

[阅读论文 PDF](https://arxiv.org/pdf/2610.31743)

## 大模型训练与对齐

### 强化学习评论器还能估计回答置信度

Free Lunch for LLMs Confidence: The RL Critic Already Knows

🌟🌟🌟

**问题**：模型说自己有把握未必可信，而专门训练置信度又可能消耗新数据并改变原有回答能力。

**结论**：以正确性作为终局奖励的评论器可以直接提供置信度；主实验不修改策略，但每次回答仍多一次价值模型计算。

**新意**：把置信度估计与价值函数学习连接起来，复用强化训练已经学到的预测目标。

强化学习中的评论器通常用来预测一段轨迹最终能拿到多少奖励。如果奖励恰好是答案正确记一、错误记零，那么在给定问题和已生成内容时，期望奖励就是答案正确的概率。这使一个原本服务于训练的组件，有机会在部署时承担置信度估计。

作者先比较同等容量的内部自估计与外部估计器，发现外部模型仅看问题、回答与正确标签，也能学到有竞争力的信号。随后直接读取近端策略优化训练中已有评论器在回答末尾的数值，并裁到概率范围；不为置信度再改写策略。实验覆盖数学、代码、工具调用与通用推理，两种八十亿参数模型在八个同分布组合中都取得最高区分能力，16组中14组校准最好。

这些结果支持把评论器当作可复用资产，而不是把模型口头报出的自信当作可靠概率。它还可在多个候选之间选答案，或者在生成过程中观察尚未完成轨迹的预期正确性。这里的依据仍然是与训练正确性奖励相连的预测，奖励若衡量其他目标，等价关系就不能原样套用。

“无需额外训练”也有明确前提：训练流程本来就有评论器。没有评论器的组相对策略方法需要再拟合价值模型，不能称为完全免费；即使已有评论器，部署也增加一次前向计算。

**编辑点评**：关键等价建立在正确性终局奖励上，不能把一般奖励数值直接解释成真值概率；域外效果仍须单独校准。

**为什么值得读**：适合已有价值模型训练流水线的团队，可优先验证复用评论器是否比另训自信表达更划算。

[阅读论文 PDF](https://arxiv.org/pdf/2610.31820)

### 只稀疏反向注意力也能加速长文微调

LazyFlash: Forward-Dense, Backward-Sparse Attention for Accelerated Long-Context Fine-Tuning

🌟🌟🌟

**问题**：长文微调的注意力反向计算很贵，但把前向也改稀疏会改变模型行为和推理部署要求。

**结论**：前向完整、反向选择性计算可维持报告中的下游质量；三万二千词元时完整训练步加速1.66倍。

**新意**：用反向开始时已知的输出梯度判断哪些查询块值得计算，并把跳过直接落实到注意力内核。

注意力训练的前向负责形成模型实际看到的上下文，反向负责计算如何更新参数。这两部分不必以同一种方式稀疏化。论文选择保留完整前向，使训练后的模型仍是普通稠密模型；只在反向阶段减少那些对参数更新贡献较小的块。

方法利用反向传播已经得到的注意力输出梯度，为查询块计算重要性。它不固定删除同样比例，而是根据每个头和每段序列的梯度分布设置保留预算，再用重要性采样补偿，保持梯度在期望上的一致。选中的权重交给定制内核，未保留块不被加载或计算，因此节省不是只体现在稀疏率统计上。

作者以相同骨干、数据次序和训练步比较不同注意力后端，并覆盖长文本与长语音。主长文实验的整体成绩为30.24，稠密基线为29.64；按随机、前向注意力质量及固定梯度比例选块的消融均较弱。三万二千词元的注意力反向最高快5.72倍，整步只快1.66倍，因为前向和其他模型计算仍在。

对工程判断而言，应先查看自身训练的耗时分解。上下文短或注意力反向占比低时，同样内核收益会被其他计算稀释。报告中的质量接近也仅覆盖这些骨干与任务，不能解释成任何预算下都无损，更不能把反向内核倍数写成整体训练倍数。

**编辑点评**：同数据和训练步对照、匹配反向耗时的消融加强了证据，但收益对上下文长度与硬件实现有明显依赖。

**为什么值得读**：适合做长文微调的工程读者：先分开测前向、反向和整步时间，再评估是否值得接入稀疏反向内核。

[阅读论文 PDF](https://arxiv.org/pdf/2610.31911)

## 评测与安全

### 科学智能体会写报告还不等于做对实验

SCI-AGENT-EXAM: Benchmarking Agents on Scientific Research Tasks

🌟🌟🌟

**问题**：科学智能体的报告流畅、代码能运行和科学结论成立，是可能脱节的几件事。

**结论**：最佳模型综合分80.9，但达到接近全通过阈值的运行只有26%；必须同时看可执行产物与报告。

**新意**：把七类科研工作流统一为代码和文本双重交付，并沿文件快照追踪已通过条件怎样在后续操作中退化。

科学任务常要求代码、数据处理、推导和报告共同成立。只让另一个模型给报告打分，可能放过无法执行的实现；只检查程序输出，也可能漏掉不成立的科学解释。论文把两类产物都作为交付要求，用程序化隐藏检查评价执行，用经专家校准的规则评价文本，再组合观察结果。

基准包含120个专家整理任务，覆盖11个科学领域和七类工作流。十个模型通过统一智能体框架在容器中运行，每任务重复三次。最佳综合成绩为80.9，但仅26%的运行达到归一化0.95成功阈值。平均分相对高，并不表示多数完整任务已经达到近乎全通过。

更有用的部分是交叉检查。不同模型中，报告较好而可执行结果较差的任务比例可达14%至48%。论文还给出相反案例：程序评分满分却缺少科学解释，或文本评分满分却只有很低程序成绩。这说明两个评价通道捕捉不同失败，不能彼此替代。

作者进一步在每次文件读写后重建快照，跟踪早期完成、退化、恢复和最终遗憾。有些条件中途通过，最后却被后续修改破坏。因此未来系统除了追求更高最终分，也值得保存已验证产物并检测回归。当前结论仍受任务包、统一框架和规则约束，不能直接解释成开放科研发现能力或真实科研生产率。

**编辑点评**：双通道评价揭示了单一总分会遮蔽的失败；基准执行成功仍不等同于科研结果通过独立复现。

**为什么值得读**：适合设计研究智能体验收的读者，可把报告主张、可执行检查和中途回归分别留下证据。

[阅读论文 PDF](https://arxiv.org/pdf/2610.32441)
