### [1] CORAL：面向生产推荐系统的原生 LLM 编排框架

> **原标题：** CORAL: An LLM-Native Harness for Production Recommender Systems

- **评分：** 9/10
- **作者/机构：** 作者机构未在已核查正文中明确标注
- **关键词：** LLM、Agent

**📌 研究问题与结论**  
CORAL 把 LLM、决策记忆、数值优化器和线上 A/B 结果组成持续闭环，在固定资源约束下调整生产推荐系统的检索与服务配置。

**🔧 方法与系统**  
每轮读取运行信号和历史决策效果，LLM 通过工具提出预算可行的配置，线上测量结果写回记忆供后续更新。

**💡 核心创新**  
将 Agent 放在生产推荐系统的持续、受约束控制面，而非只用于离线建模或单次推荐。

**🏋️ 训练与数据**  
无参数更新；在两个大型社交平台表面用线上 A/B 实验评估持续配置决策。

**📊 结果与证据**  
一项实验让新低信号用户视频会话提高 0.23%；另一项在参与度无统计显著下降下，经两轮把年化容量节省较第一轮提高 44%。

**🧐 编辑点评**  
真实大规模 A/B 证据强，但系统和数据不可公开，外部团队难以复现，也需高度可靠的约束与人工治理。

**⭐ 为什么值得读**  
适合已有实验平台、强约束优化器和回滚机制的大型推荐团队；不宜直接照搬到缺少观测与治理的系统。

[arXiv 原文](https://arxiv.org/abs/2609.02730) · [PDF](https://arxiv.org/pdf/2609.02730)

### [2] Repo-To-Skill：将 GitHub 仓库蒸馏为 AI4AI 技能

> **原标题：** Repo-To-Skill: Distilling GitHub Repositories Into AI4AI Skills

- **评分：** 9/10
- **作者/机构：** 作者机构未在已核查正文中明确标注
- **关键词：** LLM、Agent

**📌 研究问题与结论**  
Repo-To-Skill 提出 DisCo：从代码仓库和论文蒸馏、验证可复用操作知识，并在 AI 研究 Agent 执行任务时按需加载 Skill。

**🔧 方法与系统**  
离线将广泛使用的 ML 仓库整理为 Skill 图和路由库，同时按具体任务生成所需的定向 Skill，并在写入前验证。

**💡 核心创新**  
把仓库中的操作知识明确建模为 Agent 的可路由、渐进加载层。

**🏋️ 训练与数据**  
构建来自 1,000 个 ML 仓库的 5,000+ Skill 库；在 MLE-bench、PaperBench、FrontierCS、PassNet 做固定设置对照。

**📊 结果与证据**  
论文报告 GPT-5.5 研究 Agent 加 Skill 后四个基准分别提高 134.3%、34.4%、9.2% 和 14.0%。

**🧐 编辑点评**  
在固定骨干与执行预算下做了有价值的有无 Skill 对照，但库的质量与可迁移性仍取决于蒸馏和验证流程本身。

**⭐ 为什么值得读**  
适合构建研究或开发 Agent 知识层的团队；需独立检查 Skill 的触发、可执行性和来源漂移。

[arXiv 原文](https://arxiv.org/abs/2609.02749) · [PDF](https://arxiv.org/pdf/2609.02749)

### [3] 医疗问答中误导性上下文的作用机制

> **原标题：** Untangling the Mechanisms of Misleading Context in Medical Question Answering

- **评分：** 9/10
- **作者/机构：** 作者机构未在已核查正文中明确标注
- **关键词：** LLM

**📌 研究问题与结论**  
该医疗问答研究比较两类误导上下文如何改变模型判断，并测试从推理轨迹或最终回答监测受污染决策的差异。

**🔧 方法与系统**  
在 MedMisBench 医疗推理子集注入伪造证据或直接断言，测量采纳、披露、轨迹时序，并以 LLM 监测器在固定误报率下检测。

**💡 核心创新**  
同时测量易受影响性、披露性、轨迹机制和可监测性，展示最终答案观察的盲区。

**🏋️ 训练与数据**  
无训练；8,627 个临床审核问题、三个推理模型。

**📊 结果与证据**  
模型对直接断言的采纳比伪造证据高 10–27 点；读取开放轨迹的引导监测器在 5% 误报下捕获 78%，只读回答最高 32%。

**🧐 编辑点评**  
临床审核基准和多模型比较较强，但结论限于注入的两类线索；开放轨迹可用性本身限制部署。

**⭐ 为什么值得读**  
适合医疗 LLM 上线前的对抗性上下文审计；实际应用仍需临床责任链与独立证据核验。

[arXiv 原文](https://arxiv.org/abs/2609.02754) · [PDF](https://arxiv.org/pdf/2609.02754)

### [4] EvalDetectBench：衡量前沿语言模型的评测感知能力

> **原标题：** EvalDetectBench: A Benchmark for Measuring Evaluation Awareness in Frontier Language Models

- **评分：** 8/10
- **作者/机构：** Xinning Li、Kemunto Ochwang’i、Aryasomayajula Ram Bharadwaj、Alexandra Souly、Robert Kirk；研究获 LASR Winter Cohort 2026 支持，作者机构未确认。
- **关键词：** evaluation-awareness、benchmark、measurement-bias

**📌 研究问题与结论**  
EvalDetectBench 测量语言模型区分评测与部署轨迹的能力，指出提问模板和部署轨迹生成模型会混淆模型排名。它测量被明确询问后的识别能力，未证明模型会自发据此改变行为。

**🔧 方法与系统**  
对轨迹追加闭式探针，将回答集成成评测概率并用 AUROC 衡量判别力；在分层的 20% 校准集从 20 个问题中选最多 5 个；按生成模型家族与交互类型进行轻量 z-score 校正，以 10% 权重混合。

**💡 核心创新**  
将探针跨模型失配和部署轨迹生成者风格偏差分开诊断，并提供可接入 Inspect 的校准与校正流程。

**🏋️ 训练与数据**  
不训练基础模型。主数据集含 746 条轨迹（413 评测、333 部署），研究覆盖 12 个判别模型；探针选择验证使用 250 条轨迹与四个模型，生成者校正验证覆盖六个模型。

**📊 结果与证据**  
§3–5 报告生成者身份解释 11.25% 的概率方差；逐模型探针相较固定探针带来 0–0.08 AUROC 增益；12 个模型的未校正混合 AUROC 为 0.76–0.89。识别评测不能直接等同于欺骗或评测作弊。

**🧐 编辑点评**  
逐模型探针校准、生成者混淆实验和公开管线具有实用价值。公开部署池并非真实流量分布，提示启动效应与诚实回答假设未解决；分层校正以同家族轨迹为代理，缺乏已知误差界。正文与图注对部分汇总模型数描述不一致，跨基准概率汇总需谨慎。

**⭐ 为什么值得读**  
适合建立 Agent 安全评测的读者，用于检查测量工具是否把文本风格当成模型能力差异。

[arXiv 原文](https://arxiv.org/abs/2609.01611) · [PDF](https://arxiv.org/pdf/2609.01611) · [代码](https://github.com/freeze-lasr/aware_bench)
