# arXiv Agent 与大模型研究简报｜2026-09-30｜精选

本期聚焦智能体执行边界、长期上下文和自我改进：既有把安全检查推进到工具提交时刻的系统，也有从代码状态、历史证据和统计验收重新设计记忆与技能更新的方法。多篇评测进一步提醒我们，合作、修订和高奖励都可能掩盖具体失败。

阅读推荐：🌟 值得关注；🌟🌟 建议阅读；🌟🌟🌟 优先精读。星标表示本期阅读优先级，不代表研究结论的可靠程度。

## 智能体系统与工具使用

### 让智能体在执行环境中受到数据流约束

Environment Steering: Using Data Flow Control to Improve Agent Utility and Safety

🌟🌟🌟

**问题**：智能体即使收到安全指令，也可能在实际调用工具时泄露数据或执行越权动作；只在模型输出前加规则，无法覆盖执行环境里的状态变化。

**结论**：把执行状态和数据来源交给环境侧的确定性策略检查后，智能体在四类安全基准上的攻击成功率显著下降，并能根据拒绝原因改走安全路径；效果取决于策略是否覆盖真实状态。

**新意**：工作把安全控制从模型自律推进到工具提交边界，以关系表记录执行状态和数据流，并用可声明、可检查的策略决定动作能否继续。

工具型智能体的风险往往出现在最后一米：模型已经生成动作，环境准备真正读写数据。仅靠系统提示、输入过滤或另一个模型打分，会把安全继续押在模型行为上。论文提出环境引导，把智能体、工具调用、数据来源和中间状态表示成关系记录，在动作提交前检查数据如何流动。若某次调用违反策略，系统不仅阻止它，还返回与策略和上下文对应的反馈，让智能体重新规划。

这种设计的关键是把“是否允许执行”变成环境可以重复计算的判断。在四个智能体安全基准中，环境侧检查普遍降低攻击成功率；在主要基准上，它相对没有防护的系统还能提高任务成功率，并报告了零攻击成功的设置。消融结果表明，带原因的重试反馈对于恢复任务很重要。

读者需要留意，零攻击并非跨场景保证。正文在不同基准和配置下仍报告残余攻击，且策略只能检查已经建模的数据与状态。未进入关系模型的副作用、错误的来源标记或新型工具接口，都可能绕过现有规则。

**编辑点评**：证据支持环境侧数据流控制能在所测基准中同时改善安全与可用性，但不能推出所有工具调用都已安全。真正部署前仍需证明状态记录完整、策略覆盖关键副作用，并测试并发与提交时状态漂移。

**为什么值得读**：它给出了可落地的系统边界：模型负责提出动作，环境负责授权并提供可恢复反馈。设计智能体工具协议、审计日志或运行时守卫时，可以直接借鉴这一分工。

[阅读论文 PDF](https://arxiv.org/pdf/2609.35807)

### 自我改写的智能体需要统计接受门槛

SAGE: A Statistical Acceptance Gate for Self-Evolving Agents

🌟🌟🌟

**问题**：自我改写技能的智能体通常只看验证集平均分，只要新版本总体更高就接受；这会永久破坏原本能解决的样例，也会放大有限样本中的偶然高分。

**结论**：逐题配对比较并加入统计接受门槛后，技能更新的回退明显减少；收益在原始验收规则最容易退步的任务上最大，但仍依赖验证集是否代表未来任务。

**新意**：论文没有继续改进生成技能的优化器，而是专门设计验收门：先检查每个样例的得失，再用假设检验判断观察到的总体提升是否足够可信。

技能自我进化包含两个不同问题：如何提出修改，以及什么修改值得留下。已有工作常把注意力放在前者，却让后者使用“平均分上涨就接受”的简单规则。论文指出，这个规则同时面临两类风险：新技能可能在少数样例上大幅得分、却破坏许多已解决样例；优化器反复尝试后，验证集上最好的版本也更可能只是噪声中的幸运者。

作者把验收写成配对统计问题。候选技能与当前技能在同一批样例上逐项比较，系统记录新解决、保持和退步，再以统计检验过滤无法排除噪声的提升。这样，验收器能明确拒绝“平均更高但已有能力退步”的更新，也减少反复搜索造成的乐观偏差。五个任务的实验显示，在基线验收最常发生回退的两个任务上，新门槛消除了观察到的回退，并得到更好的最终技能。

代价是需要更细的验证记录和足够样本。若验证集遗漏关键用户场景，统计显著也只说明在这批样例上可信；门槛过严还可能放慢真正有益的更新。

**编辑点评**：实验直接比较了验收规则并分析回退，因果链条较清楚。结论适用于可重复评测的技能优化循环；对于只有少量昂贵真实任务的系统，如何构造代表性配对验证仍是主要难点。

**为什么值得读**：它把智能体自我改进中常被忽略的“接受候选版本”变成一等组件。任何自动改提示、技能或工作流的系统，都可以用逐例回退和统计置信度替代单一平均分。

[阅读论文 PDF](https://arxiv.org/pdf/2609.36043)

### 持久记忆应被当作从历史推出的结论

Memory Is a Derivation: The Distributed-Evidence Paradox in Long-Term Agents

🌟🌟🌟

**问题**：长期记忆会把多轮交互压成短结论，但相关证据可能散落在历史各处；引用不足会误杀正确记忆，组合多个真片段又可能产生历史从未支持的强结论。

**结论**：扩大到写入前完整历史后，接近六成原本看似缺证据的记忆获得支持，但仍有约两成保持无支持；更长证据并没有让记忆准入自动可靠。

**新意**：论文把记忆写入视为一次可审计的推导，分别检查证据范围、组合含义和准入决策，而非只判断单条引用是否与记忆表面相似。

智能体写长期记忆时，做的并非普通摘要，而是在把历史中的若干事实变成未来任务可以直接使用的前提。这一步一旦错了，后续回答会把错误记忆当成既定事实。论文提出三层审计：先检查写入器给出的引用是否遗漏了更早证据；再判断多条各自成立的事实合在一起后，是否引入了新的关系、状态或因果；最后观察验证器是否真的能挡住不受支持的记忆。

在两套自然记忆语料上，将检查范围扩大到写入前历史，能为接近六成“仅看引用似乎无依据”的记忆找回支持。这说明只审计随记忆附带的少量引用会制造大量假阳性。但扩展之后仍有约百分之十七到二十一的记忆没有充分依据。受控实验进一步显示，把更多历史交给验证器并不会自然解决准入问题，有些模型反而更容易被分散信息迷惑。

这项工作没有给出万能的记忆写入器，它更像一套证据纪律：引用覆盖、组合有效和准入可靠必须分别测量。

**编辑点评**：自然语料审计与受控配对实验相互补充，支持“扩大证据范围不等于可靠准入”。具体比例受语料、写入器和验证器影响，不应当作所有记忆系统的固定错误率。

**为什么值得读**：如果系统允许记忆影响未来决策，这篇论文提供了很实用的审计框架：先恢复写入时可见的历史，再检查组合语义，最后单独评估放行器，而不是相信一个相关性分数。

[阅读论文 PDF](https://arxiv.org/pdf/2609.36130)

### 代码改动时同步改写智能体上下文

StateTape: Action-Conditioned Evidence Lifecycle Modeling for Long-Horizon Coding Agents

🌟🌟🌟

**问题**：长程编码智能体不断修改仓库，旧观察会因后续写入而失效；按对话顺序截断或总结历史，无法知道哪些证据已过时、下一步又缺哪段代码。

**结论**：把上下文维护绑定到每次代码写入，并利用代码依赖关系增删证据后，多个长程编码基准上的解决率和上下文效率改善；收益依赖仓库结构分析与管理器质量。

**新意**：论文把上下文从被动的聊天历史改成随仓库状态更新的证据带：写入代码时同步撤销失效记录，并补入受改动影响的相关代码。

编码智能体的上下文有一个特殊难题：它自己会改变被观察的对象。某段函数、测试结果或错误分析在一次修改后可能已经过期，而传统的截断、摘要或语义筛选仍把历史当作静态文本。论文先用诊断数据测量“智能体当前携带的内容”和“下一步真正需要的代码”之间的差距，再设计随写入动作更新的上下文带。

每当智能体修改仓库，系统利用代码图判断哪些旧证据被新版本否定、哪些下游代码可能受到影响。它清除已经失真的记录，并把下一步可能需要的代码补进有限预算，而不是等待模型再次搜索。作者在多项需要连续编辑的编码任务中，以不同模型和执行框架测试这一机制，报告了解决率与上下文使用的改善。

这种方法把上下文管理变成仓库状态管理，代价是必须可靠解析代码关系。动态语言、生成代码、构建产物或跨服务依赖若没有进入图中，系统仍可能保留过期证据或遗漏关键影响。

**编辑点评**：实验覆盖多种模型与长程编码基准，说明方法并非只对单个代理有效。但它验证的是所选仓库和关系图上的收益，不能代替真实项目中的构建、运行和外部依赖核查。

**为什么值得读**：它抓住了编码智能体与普通对话助手的根本差别：每次写操作都会改变证据。构建代码代理、增量索引或长任务记忆时，这一状态联动比简单压缩历史更值得参考。

[阅读论文 PDF](https://arxiv.org/pdf/2609.36319)

### 允许语言模型直接维护自己的上下文

Context Language Models

🌟🌟🌟

**问题**：长任务的上下文通常由外部框架截断或总结，模型只能被动接受结果；固定策略很难同时适应深度搜索、长程编码和多个智能体的不同信息需求。

**结论**：让模型把上下文当作可读写文件自行维护后，论文在搜索、十二小时任务和多仓库协作中报告更高准确率与更少计算；开放写权限也形成新的注入和审计风险。

**新意**：上下文管理从框架的固定预处理变成模型可以学习和优化的动作，单智能体和多智能体都通过文件接口保留、重写或删除当前工作记忆。

大多数长程智能体把上下文管理交给外部框架：达到长度阈值后统一摘要，或按检索分数塞回若干片段。论文提出另一种接口，把上下文视为模型拥有的文件，允许模型在运行中读取、改写和组织它。模型因而可以根据当前目标决定保留什么、何时压缩以及如何为下一阶段重排信息；多智能体场景则把各自上下文表示为并存文件。

作者先用现有模型进行零样本测试。在长程搜索任务中，这种接口相对强基线提高准确率并减少计算；在十二小时的持续任务和二十四小时多仓库协作中，也报告了更好的得分或同等计算下更大提升。由于管理行为成为模型动作，研究者还能用自然语言技能优化或强化学习继续训练策略。

灵活性同时扩大攻击面。模型可能误删证据、把恶意内容写进长期上下文，或通过共享文件影响其他智能体。文件修改需要版本记录、权限边界和恢复机制，论文结果也尚不能证明所有任务都适合让模型完全自治。

**编辑点评**：跨搜索、编码和多智能体任务的结果支持接口具有普适潜力，但各项实验的模型、时长和指标不同。准确率与计算节省不能代替对上下文删除、跨智能体写入和恢复能力的安全评估。

**为什么值得读**：它把上下文管理提升为智能体可学习的核心能力，也提供了一个简单可组合的文件抽象。设计长任务框架时，读者可以同时借鉴其自治接口与必须补上的版本、权限和审计机制。

[阅读论文 PDF](https://arxiv.org/pdf/2609.37725)

## 评测与安全

### 工具动作提交时重新绑定授权状态

Boundary-State Control for Tool-Using Language-Model Agents: Commit-Time Consistency under State Drift

🌟🌟🌟

**问题**：智能体提出工具动作时通过了授权，并不代表真正提交时仍然允许；用户撤销许可、资源状态变化或动作被替换，都可能在两者之间制造安全空档。

**结论**：将单次许可同时绑定具体动作与关键授权状态后，机制在受控重放和状态漂移测试中拒绝了所有已定义的无效提交，同时保留所有未变化提交；未知状态仍取决于投影是否完整。

**新意**：论文把安全检查延伸到副作用真正发生的提交边界，并使用可解释的授权状态投影，而不是只保存一个不透明令牌或相信规划阶段的检查结果。

工具智能体常把“决定做什么”和“真正执行”分成两个时刻。若在规划阶段检查权限，随后环境发生变化，原许可就可能被错误复用。论文将这一问题称为提案到提交的状态漂移，并设计一次性提交授权：它不仅绑定动作内容，还绑定当时支撑授权的语义状态，例如权限版本、审批对象和策略身份。

真正提交时，执行边界重新计算当前状态的投影并与许可核对。动作被替换、授权撤销、策略升级、审批对象改变或令牌重放都会导致拒绝。论文先确认该边界不会改变未受攻击智能体的原生行为，再在冻结提案、独立生成的状态漂移和外部连续性测试中逐类验证。对预先定义的变化类别，它保留全部有效提交并拒绝全部无效提交。

这些零错误结果证明了机制对已建模类别的闭合性，而非未知环境中的绝对安全。若语义投影遗漏某个会改变授权的字段，提交比较仍可能把危险变化视为相同状态。

**编辑点评**：实验把不干扰正常行为、字段作用、漂移选择性和重放生命周期分开测试，证据结构很扎实。结论边界也明确：安全性最终落在执行点可信度与语义投影完备性上。

**为什么值得读**：它给工具协议一个清楚的事务模型：规划阶段产生带条件的一次性许可，提交阶段按当前状态重新验证。涉及外发消息、改基础设施或处理敏感数据的智能体尤其值得采用。

[阅读论文 PDF](https://arxiv.org/pdf/2609.37475)
