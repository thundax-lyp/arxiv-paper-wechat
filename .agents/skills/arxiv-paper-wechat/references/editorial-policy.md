# 固定编辑质量规范

本文件是论文筛选、方向分类和评分的唯一质量口径。开始读取当天论文前必须完整阅读；同一期内不得改变标准。流程、存储或 CLI 重构不能隐式修改本规范。

## 过滤范围

`keep` 表示论文的核心问题、方法或主要结论对 Agent/LLM 读者有实质价值，而不是标题或摘要碰巧出现关键词。

保留以下方向：

- autonomous、embodied、web、coding、research agent，以及 agentic system
- tool use、function calling、computer use、workflow orchestration、memory
- LLM reasoning、planning、reflection、long-context、RAG 与知识检索
- multi-agent collaboration、negotiation、simulation、communication
- LLM training、alignment、preference optimization、RLHF、DPO、safety、guardrail
- Agent/LLM evaluation、benchmark、hallucination、reliability、robustness
- 具有明确 agentic 行为或重要 LLM 方法贡献的应用与基准

剔除以下工作：

- 纯 CV、机器人控制、图学习、优化、博弈论或社科仿真，且没有 LLM/Agent 方法连接
- 普通 NLP 分类、抽取或生成任务，未涉及 LLM、agent、tool use、reasoning 或 RAG 方法贡献
- 仅把 LLM 当作标签器、数据生成器或无关组件，主要贡献与 Agent/LLM 无关
- 只在标题或背景中营销式提及 Agent/LLM，技术贡献不属于本简报范围

边界论文按“主要技术贡献是否值得核心读者阅读”判断。不能仅靠关键词决定；`drop` 必须写出可核查的具体理由。

## 固定 Taxonomy

每篇 `keep` 论文只能选择一个主方向：

- `Agent系统与工具使用`：智能体架构、工具/函数/计算机调用、记忆、工作流、软件与具身智能体系统
- `LLM推理与规划`：推理、搜索、规划、反思、长上下文和测试时计算
- `RAG与知识检索`：检索增强生成、知识访问、索引、查询和事实性增强
- `多智能体与协作`：多智能体通信、协商、分工、博弈、群体模拟与协作学习
- `LLM训练与对齐`：预训练、微调、蒸馏、偏好优化、RLHF/DPO 和行为对齐
- `评测与安全`：评测、基准、可靠性、幻觉、鲁棒性、风险、攻击与防护
- `应用与基准`：面向具体领域的实质性 LLM/Agent 应用，或不更适合前述方向的新基准
- `其他 Agent / LLM 方向`：确属范围但无法合理归入前述方向；不得作为避免判断的默认项

存在多个贡献时，按论文最主要、证据最充分的贡献选择主方向，其他内容放入 `tags`。

## 评分口径

按 ML/NLP 顶会审稿尺度独立评分，总分由 CLI 复算：

### 新意 `novelty`（0–3）

- `0`：没有可辨识的新贡献，或主要是已有方法复现/包装
- `1`：局部增量或已知组合，改进有限
- `2`：问题、方法或系统设计有清楚且有意义的新意
- `3`：提出可能改变研究或系统实践的新范式、新能力或关键洞见

### 影响力 `impact`（0–3）

- `0`：与主线读者几乎无关
- `1`：适用面窄，主要影响小众任务或设置
- `2`：对一个重要 Agent/LLM 方向有明确价值
- `3`：可能广泛影响多个方向、基础能力或实际系统

### 证据强度 `evidence`（0–2）

- `0`：关键结论缺少可信实验、比较或分析支撑
- `1`：主要结论有基本支撑，但基线、消融、规模、统计或失败分析存在明显缺口
- `2`：实验设计、强基线、消融与分析较完整，结论和证据边界一致

### 受众匹配度 `audienceFit`（0–2）

- `0`：核心读者无需关注
- `1`：与核心主题相邻，对部分读者有价值
- `2`：直接命中 Agent、LLM、RAG、对齐、评测或安全核心关注

总分 `>= 7` 才进入精选。`keep` 与“精选”是两个判断：相关且值得记录的论文可以保留但不进入精选。高分必须克制，不能因为使用 LLM、数据规模大、来自知名机构或声称 SOTA 而自动加分。

## 阅读与证据要求

- 每篇论文至少阅读转换后 Markdown 中的摘要、方法、实验和限制相关内容；重要或表述含糊的论文继续核对全文上下文。
- `summary` 描述论文实际解决的问题和结论；`critique` 明确证据强弱、局限和适用边界，不能改写成宣传文案。
- `method`、`innovation`、`training`、`results` 必须能在论文中找到依据；不适用或论文未披露时明确写出，不得猜测。
- 作者机构和代码地址必须从论文正文、附录或明确链接核实。没有代码链接时保留空字符串，不得编造。
- 评分先按四个维度独立给出，再写推荐理由；不得先决定精选再倒推分数。


## 全文细筛上限

对最终下载候选完成正文阅读后，最多保留最重要的 40 篇，不足不凑数。先独立评估四项质量维度，再按总分降序衡量重要性，同分按 arXiv ID 排序；相关性排序不能替代全文质量判断。范围内但未进入前 40 的论文也写 `drop`，明确说明其贡献、证据或适用面为何优先级较低，并保留比较所依据的维度判断。CLI 拒绝超过 40 条 `keep`；正式编辑输入仍须覆盖全部可编辑候选。
