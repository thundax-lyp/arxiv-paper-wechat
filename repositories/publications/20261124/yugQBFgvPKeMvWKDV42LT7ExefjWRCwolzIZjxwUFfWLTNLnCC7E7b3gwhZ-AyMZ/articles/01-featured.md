# arXiv Agent 与大模型研究简报｜2026-11-24｜精选

本期关注模型与执行框架的分工：实时代理如何跟上环境，研究代理怎样保存试验，以及工具只返回部分结果时如何复核。另外几项工作讨论了把长任务拆成短调用，以及如何衡量安全评测和蒸馏带来的差异。

阅读推荐：🌟 值得关注；🌟🌟 建议阅读；🌟🌟🌟 优先精读。星标表示本期阅读优先级，不代表研究结论的可靠程度。

## 智能体系统与工具使用

### 让视觉智能体在下一次推理前继续行动

AutoPILOT: A Visual Agent Harness for Real-Time Gameplay

🌟🌟🌟

**问题**：环境在模型推理时持续变化，逐轮生成的动作如何跟上？

**结论**：在所测浏览器游戏、同模型和预算下，将快速动作交给执行层，实时成功率由百分之三十八点三升至六十八点六。

**新意**：让模型一次调用可以交付读屏闭环控制器，并在需要新的判断时收回控制。

在可暂停的游戏里，模型可以观察、推理、行动，再等环境根据这一步作出反应。实时环境没有这层保护：分析画面的几秒里，角色可能已经走过转弯口，或者需要躲避的物体早已换了位置。即使模型给出的下一步本来正确，等动作执行时也可能失效。旧框架在记忆和视野上做得更好，仍受一轮推理只执行一个动作的节拍限制。

作者为同一接口提供三种动作粒度。需要精细判断时仍可给单步指令；路径稳定时，可提交一串按顺序执行的按键；需要经常看屏幕修正时，则让模型写出短控制程序，持续观察画面并快速调整。程序接手后不必等模型逐帧响应。完成或遇到需要重新规划的情况，再把控制交回模型。三种方式可以在同一场游戏中切换。

作者为一百二十款浏览器游戏提供暂停和实时两类测试条件，在同模型和预算下，实时成功率从百分之三十八点三升到六十八点六。在另一个游戏集，旧框架从暂停时的百分之八十四点一降到实时的四十二点九，新框架在实时条件保持百分之八十。同样重要的是撤去控制器和连续动作的对照：失败常由模型调用限额耗尽引起，显示动作刷新频率本身会拖累成绩。

**编辑点评**：结果来自具备可读画面、可模拟按键与可测成功条件的游戏，物理设备上的传感噪声、控制风险和验证开销未经过测试。

**为什么值得读**：真实应用可以分别为高层规划与低层控制设定刷新周期，并把交还控制的条件纳入测试。

[阅读论文 PDF](https://arxiv.org/pdf/2611.28202)

### 自动研究智能体该如何保留试验记录

Demystifying the Autoresearch Harness: How Context and Skills Shape Self-Evolving Agents

🌟🌟🌟

**问题**：自动研究智能体跨许多轮试验时，应当存下哪些历史，又应当清理哪些经验？

**结论**：按试验保存可回查简档在三种模型与两类任务的六组比较中都胜出，技能侧删掉长期未用的经验平均更有效。

**新意**：在同一个研究循环中分别替换上下文与技能模块，让单项记忆设计的贡献可以比较。

自动研究智能体通常反复做同一件事：提出新设想，修改程序，执行并读取反馈，再决定下一轮尝试。历史一长，框架必须压缩上下文。只保留最近几轮很便宜，但早先的失败条件或最佳实现会消失。用一段滚动总结覆盖全部历史，又容易把试验之间的区别抹平，模型以后即使想复查，也很难找回特定一轮。

研究保留同一套执行流程，只替换记忆模块做比较。所谓折叠，是在一轮结束后把具体操作收进一份短记录，同时让智能体能按需要找回那一轮；滚动压缩则把过往内容持续提炼进共享摘要。另一组实验处理经常被叫作技能的经验条目，比较将经验合并、升格为常驻规则，或删去长期没有实际使用的条目。这样可以把试验史是否好查，与经验条目是否应长期留下，分成两个可测的问题。

折叠在机器学习竞赛与计算内核优化的六个模型任务组合中全部优于近期截断，最大相对收益为百分之十九点二。作者组合折叠和技能删减后，在轻量竞赛里拿到百分之七十二点七的奖牌率。这里的关键条件是两类任务都能迅速执行程序、比较结果，经验是否有用有相对明确的反馈。研究没有测过反馈稀疏或目标会中途改变的场景。

**编辑点评**：六组对照支持折叠的稳定性，但最佳单组相对收益高于平均收益，完整组合的成绩也无法归给单个机制。

**为什么值得读**：设计长程代理时，可以分别验收单次试验的回查能力和技能条目的实际使用情况。

[阅读论文 PDF](https://arxiv.org/pdf/2611.28244)

## 大模型推理与规划

### 递归调用让短任务训练迁移到长任务

Language Model Harnesses can be Compositional Generalizers

🌟🌟🌟

**问题**：训练数据里的短任务，如何帮助智能体完成长度远超训练的任务？

**结论**：将任务分成模型熟悉的局部调用后，短任务强化学习在所测场景迁移到长二至六十四倍的输入。

**新意**：用程序外置上下文并学习分解，再用便宜的合成替身任务训练真实框架中的局部调用。

语言模型作为智能体并不会天然越做越稳。有一种运行方式是在同一个提示里一路累加工具回执、过去的判断和当前目标，任务变长后，就要求模型学会处理训练时很少见的轨迹。作者试验的另一种方式是把原始材料放到外部，让主模型写程序挑取局部材料，或让下一级模型解答局部问题，最后按程序逻辑组合结果。这样，个别调用看见的内容可以保持很短，整体问题却可以远长于训练样本。

由此可以把训练拆成两个问题。主模型要学会在哪里切分、如何组织调用，子模型要能完成切出来的任务。研究用强化学习在较短输入上训练分解，再测试更长输入以及拥有相似潜在结构的不同领域。递归框架在长度和部分跨域场景的迁移强于直接调用的基础模型。作者还用伪造的子调用结果构造容易批量生产的替身环境，训练主模型处理组织过程，减少复刻整个目标环境的需求。

这种结果为训练投入提供了一个可测试分解：模型缺的是某个局部技能，还是调度这些局部技能的结构？前者需要补足任务能力，后者可能用较小的替身练习。若任务无法分解，或局部输出组合时丢失约束，成功迁移的前提便不成立。

**编辑点评**：结果最强的环境有可利用的分解结构。没有证据表明任意复杂任务都能按长度倍数外推，额外调用也有推理开销。

**为什么值得读**：构建训练环境时，可先测分解策略能否单独迁移，再决定要不要昂贵地复制生产环境。

[阅读论文 PDF](https://arxiv.org/pdf/2611.28298)

## 大模型训练与对齐

### 蒸馏时隐藏学生推理，减少多轮智能体的输出

Muted Distillation: Sealing Reasoning from Teacher Unlocks Token-Efficient Agents

🌟🌟🌟

**问题**：用高效教师蒸馏多轮代理，为何有时学生输出反而更长？

**结论**：教师评分时屏蔽学生思考后，两个基准的任务输出分别比常规蒸馏减少百分之五十七和五十三，准确率持平或提高。

**新意**：继续学习学生实际产生的行动轨迹，同时改变教师可见的上下文来减少思路之间的干扰。

在常见的在策略蒸馏中，学生先自己行动，再由教师对学生遇到的位置评分。这样教师看到的是学生确实会经过的状态，但多轮任务中，这些状态往往带着学生刚写下的长篇思路。教师即便习惯直接行动，一旦接在一段未结束的思考之后，也可能给继续展开推理的词更高分。学生从这样的监督中学到的行为，可能比蒸馏前更长。

这个方法保留学生生成轨迹，只在教师评分这一侧遮住思考文本。教师仍然能看到对外的行动、工具回执和任务进展，因此可以判断下一步是否合理；它不必接着学生的内部文字续写。对照两种训练方式可以看出，教师可见的上下文也是监督信号的一部分，不同于只调整任务答案、奖励或训练规模。

以一个较大教师训练四十亿参数学生时，两个知识工作基准每次任务的输出量分别比常规蒸馏少百分之五十七和五十三。文档问答准确性大体相当，表格任务一次通过率高四点八个百分点。作者还考察了较大体量学生，但所测任务都有清晰的行动和工具边界。输出缩短能节省生成开销，实际总延迟还取决于工具耗时、输入及缓存。

**编辑点评**：结果支持文档和表格任务中的节省，开放规划、不同教师和未显式分离思考的轨迹需要另测。

**为什么值得读**：检查蒸馏教师读取的轨迹表示，分开衡量正确率、输出长度和端到端开销。

[阅读论文 PDF](https://arxiv.org/pdf/2611.28445)

## 评测与安全

### 工具少返回数据时，智能体为何会编造答案

When Tools Fail, Agents Fabricate: Silent Failure and Verification-First Oversight in Tool-Using LLM Agents

🌟🌟🌟

**问题**：为什么返回了部分数据的工具比明确报错更容易让智能体给出错误结论？

**结论**：在三十个沙箱任务中，核验优先的监督器让正确恢复率提高十点七个百分点，同时把编造率降低六点五个百分点。

**新意**：用可控的工具故障和独立真值区分静默采纳、诚实失败与真正恢复。

工具错误通常让人想到网络断开、权限不够或明确失败。对智能体而言，还有一种更难处理的形态：同一次调用表面上成功了，却只返回了其中一部分数据。如果代理既不知道预期范围，也不检查结果完整性，就可能把表面可用的数据直接编进结论。此时重新生成答案并不能补回缺失事实。

作者在带真值的控制环境中，让四个模型代理完成三十个多步任务。环境有真实的文件操作和数据库，也允许固定故障种类与持续时间。研究独立核对最终答复，区分恢复正确、如实报告失败和编造。两千一百次有故障的运行表明，部分回传特别容易诱发编造，某些条件可高达百分之三十八。明确拒绝访问时，代理反而更常承认无法完成。许多错误在第一次接触不完整数据便已发生，并非多次失败以后才出现。

研究再加一层先核验的监督流程，依据结构化工具回执向代理指出需要纠正或再次核实的地方。正确恢复率由百分之四十五点六增至五十六点三，编造率从十七点三降到十点八。两个数字应一起读：仅仅令模型遇疑即停，也可能压低编造，却无法增加真正完成的数量。

**编辑点评**：任务有明确真值且故障受控，开放式工具输出的完整性常难以独立核对，监控策略需要按具体工具和风险验证。

**为什么值得读**：制作验收集时，把回执部分缺失和明显失败分别注入，并同时考察真实恢复与如实告知失败。

[阅读论文 PDF](https://arxiv.org/pdf/2611.28341)

### 红队评测会随有害性判据改变

What Counts as Attack Success? Evaluating Harmfulness in Red Teaming LLMs

🌟🌟🌟

**问题**：同一批模型答复交给不同裁判时，红队报告中的成功率还能互相比较吗？

**结论**：在固定输出的对照中，不同判据可以让两种模型的脆弱性顺序反转。

**新意**：同时追踪文献里的危害定义、实际打分工具和计分阈值，并把裁判差异放到同一批答复上检查。

红队评测的一个常见做法，是用成功率比较两种模型的安全性。计算步骤虽然简单，分子的含义却可能不同。有的裁判把没有出现拒绝句式算作成功，有的裁判还会问答复是否服从了请求，或是否提供了足以造成危害的内容。一段带着玩笑语气的胡编故事，在这些定义下可能被分到不同类别。把结论写成一个百分比，会把这些选择藏起来。

作者先梳理七十六篇论文，发现只有五篇提出自己的有害性定义，二十三篇没有给出定义。许多工作沿用了既有数据集、分类器或模型提示的口径。随后，作者固定两种语言模型在同一测试集上的输出，只替换八个判定器，并从其中一个试验条件下抽出一千零四十条作为人工标注参考。八个判定器在大部分答复上意见一致，争议集中在少数边界样本，却足以改变一些模型间的小差距。人工参考判定两种模型的成功率分别为百分之四点二与五点零。部分自动裁判给出的排序彼此相反；其中一个反向差异经多重比较校正后仍然显著。

这也解释了为什么公开裁判名称还不够。同一个打分模型，调整及格线，成功率也会明显变化。若比较的差距很窄，就需要把危害定义、评分阈值和边界样本的问题一起展开，否则指标变化很难归因到模型本身。

**编辑点评**：实验以英语、两种模型和一个测试指令集为主，人工参考由单一标注者提供，不能代表普遍认可的危害标准。

**为什么值得读**：论文提供了可迁移的对照做法：固定输出重评分，再追踪导致排序变化的边界样本。

[阅读论文 PDF](https://arxiv.org/pdf/2611.28038)
