# arXiv Agent 与大模型研究简报｜2026-09-21｜精选

本期最值得关注的是智能体训练环境、开放任务信用分配、混合计算机使用与内部安全审计。多篇工作共同提醒：局部得分、流畅交互和平均通过率都可能掩盖端到端失败，真正可靠的系统需要可执行验证、过程证据和清晰的适用边界。

阅读推荐：🌟 值得关注；🌟🌟 建议阅读；🌟🌟🌟 优先精读。星标表示本期阅读优先级，不代表研究结论的可靠程度。

## 智能体系统与工具使用

### 能打断、能插话、还能调用工具的全双工语音智能体

NemotronLabs VoiceChat: An Open Full-duplex Speech-to-Speech Model with Tool Calling Capabilities

🌟🌟🌟

**问题**：实时语音智能体通常难以同时听取、插话恢复、调用工具并自然说话，多个串联系统还会累积延迟。

**结论**：统一流式模型能在保持全双工交互的同时完成结构化工具选择，但参数填写和完整执行仍明显落后。

**新意**：模型用并行输出流分别承载回复文本、函数调用、增量转写和语音生成，把原本串联的能力放进同一时间轴。

这项工作的重点不是把语音识别、语言模型和语音合成简单串起来，而是让它们共享实时交互节奏。模型一边接收用户声音，一边维护增量转写与推理状态，同时可输出自然语言回复或结构化函数调用；用户打断时，系统必须停止、接管并在合适时机恢复，而不是等整段音频结束后重新开始。多组全双工基准显示，它在暂停处理、用户打断后的接管与恢复方面达到较强水平，工具选择也取得较高分数。这证明“听、想、调用、说”可以在开放模型中统一，而无需牺牲基本实时性。不过，工具选择正确只是第一步：参数是否准确、函数是否真正执行成功仍是薄弱环节。对实际语音助手而言，流畅对话容易给人已经可靠完成任务的错觉，因此必须把交互体验与执行结果分开测量。

**编辑点评**：语音交互实验覆盖多个专门基准，优势集中在时序行为与工具选择；端到端执行证据较弱，不能据此推断它已适合高风险事务。

**为什么值得读**：它把语音智能体的系统边界讲得很清楚：真正的全双工不是更快的语音输入输出，而是让工具调用也服从实时对话的中断与恢复机制。

[阅读论文 PDF](https://arxiv.org/pdf/2609.21967)

### 复刻真实应用，检验能看界面也能写代码的智能体

RecreationWorld: Scalable and Verifiable Environments for Hybrid Computer-Use Agents

🌟🌟🌟

**问题**：现有智能体往往只会操作界面或只会写代码，难以在真实任务中自行往返探索、实现和视觉核验。

**结论**：以运行中的参考应用作为行为裁判，可以规模化生成混合轨迹并促进迁移，但完整复刻交互的成功率仍极低。

**新意**：“复刻应用”同时提供未知规格、可执行参照和隐藏行为测试，把混合计算机使用变成可训练也可自动验证的长程任务。

真实的软件工作很少只发生在终端或只发生在图形界面。开发者会先操作现有产品理解行为，修改代码，再运行并查看成品是否符合预期。本文把这条循环变成统一任务：智能体只能接触运行中的参考应用，需要自行探索状态变化，编写可运行实现，并反复用视觉与程序反馈修正。框架覆盖五类操作平台，参考应用既是隐含规格，也是生成隐藏测试的行为裁判。用高分轨迹训练后，模型在多个分布外编码与混合计算机使用基准上提升，也更常主动检查自己的渲染结果。与此同时，留出基准暴露了巨大缺口：最强系统总分虽领先，但能通过全部程序检查的任务不足百分之三；静态界面容易模仿，交互、计算结果和持久状态远难复刻。

**编辑点评**：任务规模、平台覆盖和程序加视觉双重检查都很扎实，迁移结果也有说服力；训练轨迹来自高质量开源应用，是否能覆盖封闭商业软件与高风险操作仍未知。

**为什么值得读**：它为“会看界面又会写代码”的智能体提供了很强的训练与评测范式，也提醒团队不要用截图相似度替代真正的行为正确性。

[阅读论文 PDF](https://arxiv.org/pdf/2609.22000)

### 只靠源代码，批量构造代码智能体训练环境

CodeMidas: Scaling Agentic Coding RL Environments from Code Itself

🌟🌟🌟

**问题**：代码智能体强化学习需要大量带可靠验证器的任务，而依赖议题和提交记录会限制可提取任务的数量与类型。

**结论**：仅从已有源代码反推功能、生成测试并严格过滤，就能构造五千余个环境，训练后在五类外部代码任务上均提升。

**新意**：它把智能体计算投入环境生产全链条，让代理探索原功能、写行为规格、构建执行测试并用反复解题验证任务质量。

开源仓库里已经实现的功能远多于公开议题，但这些功能没有现成的自然语言任务和隐藏测试。本文让多个智能体先运行、阅读并探索代码，提炼行为规格；再以原实现的真实执行结果为依据生成测试；最后检查环境一致性，并通过多次解题轨迹剔除太容易、含糊或验证不稳的任务。得到的数据横跨三千余个仓库、二十多种编程语言和多类技术领域。用这些任务做强化学习后，同一模型在仓库修复、完整程序构造、代码迁移和终端操作等五个外部基准上全部改善，且轨迹分析显示它更愿意探索代码库并采用多样化自检。关键价值不只是数据量，而是说明“已有代码本身”可以成为可扩展环境源。风险在于，原实现未必就是正确规范，自动测试也可能只覆盖表面行为。

**编辑点评**：跨五个外部基准的一致提升和数据规模构成较强证据；但规格与测试都由智能体从原代码推导，隐藏缺陷或不完整覆盖可能被当成真值。

**为什么值得读**：训练代码智能体的瓶颈正从模型转向环境。本文展示了如何把环境构造也做成智能体流水线，并用执行与多轮解题为质量把关。

[阅读论文 PDF](https://arxiv.org/pdf/2609.22068)

## 大模型推理与规划

### 把深度研究轨迹改造成长上下文训练材料

Boosting Deepresearch and LongContext Ability with Self-Generated Deepresearch Rollouts Traces

🌟🌟🌟

**问题**：深度研究智能体会不断积累搜索历史与网页证据，强化学习后的剩余错误大量来自长上下文整合不足。

**结论**：把研究轨迹扩展成完整多文档问答，再经历“研究、长文、研究”三阶段训练，可同时提高研究与长上下文能力。

**新意**：它不另造长文标注，而是用原轨迹的链接与答案监督，把摘要替换为完整网页，保留证据依赖关系。

深度研究的训练轨迹天然包含查询、访问页面、证据片段和最终答案，但常见训练只保留压缩摘要，模型因此没有被迫处理真实长度的多文档上下文。本文先做一小段研究强化学习收集轨迹，再把每条轨迹中的网页摘要替换成对应完整正文，形成无需新增人工标注的长上下文问答；模型完成长文强化学习后，再回到完整的研究强化学习阶段。与只持续训练研究任务相比，这种三阶段安排在三个深度研究基准上平均提高约七个百分点，在三个长上下文基准上提升更大。分析还发现，长上下文能力增强后，智能体的工具使用偏好会发生变化，说明阅读能力与检索行为并非独立模块。限制在于网页内容会变化、链接可能失效，原轨迹若证据关系错误，扩展后只会放大噪声。

**编辑点评**：同等训练步数下同时比较研究和长文能力，证据较完整；但数据构造依赖网页快照可重现，且自动裁判与原答案监督可能继承错误。

**为什么值得读**：它给研究智能体团队一个低成本数据策略：不要把长上下文训练与工具轨迹分开采购，真实搜索过程本身就能转化为多文档学习材料。

[阅读论文 PDF](https://arxiv.org/pdf/2609.20844)

## 多智能体与协作

### 开放任务强化学习，把胜负信号传到关键步骤

ArenaFlow: From Trajectory Ranking to Hierarchical Credit Propagation for Open-Ended Agent RL

🌟🌟🌟

**问题**：开放任务没有可靠标量奖励，整条轨迹的胜负也无法说明究竟哪一步值得学习。

**结论**：把相对排序进一步分解到关键步骤和可复用技能后，旅行与深度研究任务都明显优于只做轨迹级优化的方法。

**新意**：它没有停在“谁赢了”，而是把比较理由变成步骤信用、技能抽象和技能使用归因三类监督。

在可自动判题的数学或代码任务里，强化学习只需看最终答案是否正确；开放式智能体任务却往往存在许多合理路线，单一分数既不稳定，也无法告诉模型哪一次检索、比较或修正真正改变了结果。本文先让同组轨迹参加相对锦标赛，用存活轮次得到较稳的整体排序；随后要求裁判明确指出胜者的关键步骤、可迁移策略，以及先前检索到的技能是否真的被用上。关键步骤获得更集中的优化信号，高价值技能则进入全局记忆，供后续探索调用。实验中，方法在开放旅行和深度研究两类任务上都超过仅用轨迹偏好的对照，并在外部研究基准上保持转移收益。这说明开放任务的比较反馈并非只能压成一个分数，结构化解释本身可以成为训练资源。代价是整个链条仍依赖裁判：若裁判把偶然相关的动作当成关键步骤，错误会同时进入参数更新和技能库。

**编辑点评**：证据覆盖两个开放任务和外部迁移，且与多种强化学习基线比较充分；但关键步骤与技能归因仍由模型裁判产生，论文没有证明这些解释在强分布变化下保持因果正确。

**为什么值得读**：它提供了一种可复用的设计思路：当最终奖励太粗时，不必先寻找完美标量，可以把成对比较转成局部步骤监督和长期技能资产。

[阅读论文 PDF](https://arxiv.org/pdf/2609.21378)

## 评测与安全

### 读出模型不愿说出的答案

A Lie Detector Test for Language Models: Reading Knowledge a Model Won't Reveal

🌟🌟🌟

**问题**：模型答错时，外部观察无法区分它确实不知道，还是知道却在刻意隐藏能力或规避评测。

**结论**：从候选答案对应的内部状态读取“被识别答案”，可在多种隐藏设置下保持高识别率，并辅助区分隐藏与真正遗忘。

**新意**：它借鉴隐匿信息测试，不需要诚实参考模型或真值训练集，而是在同一问题的候选内部做对比读取。

能力评测通常只看最终输出，这给“装不会”留下空间。本文把正确答案与若干诱饵一起呈现，读取模型在候选末尾的内部表示，再利用题目内部的对比方向判断模型最认可哪一个选项。跨五个模型家族、八个模型的实验表明，即使模型因提示、专门训练、密码锁或回路阻断而输出错误答案，内部识别仍经常保留。进一步地，若机器遗忘真正移除了知识，读取信号会下降到从未学过该题的水平；若只是把输出封住，信号仍然存在。这为能力隐藏审计和遗忘核查提供了不同于行为测试的证据。边界也很明确：方法需要访问内部激活，最好还要有可枚举候选；它无法区分“从未学会”和“已经删掉”，也挡不住专门针对探针训练的对手。

**编辑点评**：跨模型与多种隐藏机制的证据较强，并包含因果操控；但威胁模型默认被测模型没有主动规避该读取方向，开放式长推理也难直接套用。

**为什么值得读**：安全评测最棘手的问题之一是把能力缺失与能力隐藏分开。本文给出一条具体、可实验复核的内部审计路线，同时坦率限定了它不是万能测谎器。

[阅读论文 PDF](https://arxiv.org/pdf/2609.21996)
