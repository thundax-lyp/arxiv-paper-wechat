## Agent系统与工具使用

### 长期记忆更新，需要区分补充、替代与矛盾

MemoryLACE: Memory Lifecycle-Aware Consolidation and Evidence Retrieval

🌟🌟🌟

长期助手面对的信息会发生变化：用户搬家了、偏好变了，或不同消息暂时互相矛盾。单纯追加摘要容易让新旧状态并列出现；直接覆盖又会丢失解释变化所需的历史。MemoryLACE 把问题放在信息之间的关系上，而不是一味扩大记忆规模。

它先从对话构建可独立理解、带来源的原子记忆，再记录少量关系：重复或互相补充的信息可以合并；新状态可以替代旧状态；尚不能解决的冲突则保留并显式关联。检索时先找到当前有效记录，再沿这些关系补入历史、支持或矛盾证据。以地址更新为例，助手需要知道现在住哪里，也应能区分旧地址曾经有效与两条信息仍待核实这两种情况。

BEAM 的十万 token 子集包含二十段对话、四百个问题。使用相同 Qwen3.5-9B 骨干时，模型裁判给出的总体分从 Hindsight 的 50.3 升至 51.9。更明显的是成本：在同一 A40 虚拟 GPU 配置和处理设置下，构建记忆加回答的总耗时由二十二小时三十分降至七小时三十一分。这个数是整套基准的运行时间，不是一次查询延迟。

代价也能从分项看到：时间推理比 Hindsight 低 8.7 分，摘要低 4.9 分。局部关系和有限证据包更省资源，却未必适合重建完整时间线或穷尽总结。因此，它值得作为记忆数据结构与检索策略来读：哪些记录已被替代、哪些冲突仍未解决，应进入系统表示；总体分的小幅领先并不意味着每种记忆任务都更好。

[阅读论文 PDF](https://arxiv.org/pdf/2609.03201)

## LLM推理与规划

### 保住问题后，随机保留推理缓存也能有竞争力

Random Attention: Rethinking KV Cache Eviction for Efficient Reasoning

🌟🌟🌟

长推理会不断积累键值缓存，也就是模型为避免重复计算而保存的历史表示。常见压缩方法先给这些内容打分，再删除低分项。这篇论文问了一个值得认真对照的问题：效果究竟来自评分准确，还是来自没有误删最关键的输入？

Random Attention 把两类内容分开处理。系统提示和题目完整保留；模型自己生成的推理过程，则由不同注意力头独立随机抽取。直觉是，题目往往只出现一次，而推理会反复重述中间结论；各头保留不同片段，又提供了额外冗余。因此，不精确挑选也可能留下足够信息。论文通过统一提示保护等消融，检查复杂方法的优势是否仍然存在。

四个模型、六类推理任务的比较中，随机方案多数情况下能与最强淘汰基线竞争。工程价值则来自省去重要性评分：单张 H200、约一千 token 输入和三万二千 token 输出的服务测试中，吞吐比 TriAttention 高 32%—43%。这是相对吞吐提升，不能理解为答案质量同步提高。

限制同样具体。Qwen3-32B 的代码任务上，TriAttention 有一次显著胜出；输出缩短到八千 token 的另一组测试中，随机方案仍比全缓存慢，因为节省内存尚不足以抵消压缩开销。完整保护提示也不适合无限长输入。它最有用的启发是：评价缓存算法时，应同时比较简单随机基线、提示保护策略和实际服务负载，避免把结构性保护的收益归功于复杂评分。

## 评测与安全

### 工具调用得零分，可能是接口没接上

Interface-Induced Trajectory Censoring

🌟🌟🌟

一个工具调用基准得了零分，通常会被解释为模型不会使用工具。但从模型输出到真正执行，中间还有聊天模板、调用格式、服务端解析器和执行器。只要其中两端约定不一致，一次已经写出的调用就可能被丢弃，后续交互也因此消失。

研究把这条链拆开记录：先看原始输出里有没有明确调用，再看服务端是否解析、工具是否执行，最后才看任务完成。关键实验固定权重、题目和解码，只改变模板与解析器的配对。模板负责教模型用什么外壳表达调用，解析器负责认出这个外壳；两者只改一端仍可能完全无效。

在 BFCL 的两百个测试用例中，配套调整使首轮可解析请求从零增至 196 个；其中多轮子集的完成任务从零增至 19/100。这并不是重新训练出的能力，而是接口原先遮蔽了部分行为。它也没有证明模型已经擅长多轮工具使用：绝大多数多轮任务仍未完成。

另一个含模拟用户的交互基准进一步划清边界。工具执行从零恢复后，完成任务只从 7/115 增至 10/115，差异未达到统计显著，且用户模拟器不同于原始排行榜。因此，不能拿恢复的调用次数替代成功率，也不能据此宣布训练方法更优。对于维护评测或代理服务的人，这篇论文的阅读价值在于诊断顺序：保留原始输出，逐层定位意图、解析、执行和结果之间的损失，再判断瓶颈属于模型还是接口。

[阅读论文 PDF](https://arxiv.org/pdf/2609.03966)

### 证据相互冲突时，排列顺序会左右答案

Large Language Models in Resolving Contextual Knowledge Conflicts

🌟🌟🌟

把多份材料交给模型，并不意味着每份材料都进入了最终判断。当材料冲突时，读者关心的是模型能否解释分歧、识别时间变化或综合不同观点，而不是恰好采纳排在最前面的说法。ContextConflict 用六类、共 5781 条冲突样本，把这种问题从一般问答中单独提出。

研究发现，模型的回答受到证据位置影响，并进一步检查内部表示是否偏向首条证据。干预方法的直觉是建立一个较少受排列影响的参照：分别输入每条证据，取得表示并求平均，再与同时输入全部证据时的表示比较。两者之差用于构造固定调整方向，在后续生成时轻推内部状态。方法不更新模型权重，但需要校准数据和内部激活访问。

实验中，Llama-3.1-8B 的时间冲突准确率提高了 19.2 个百分点，说明干预不仅改变了表达，也改善了特定推理任务的答案。摘要任务则采用另一套标准：估计各证据对生成文本的贡献，再衡量贡献是否失衡。这种贡献由外部评分模型近似计算，不能直接等同于人的理解或模型真实的内部因果过程。

阅读时尤其要保留一个前提：摘要实验把不同来源视为同样有效。真实检索中，过期记录、可信文档和未经核实的说法本就不应平均对待。因此，这篇工作适合帮助我们识别“位置偏好”，并设计打乱证据顺序的对照；它没有给出普遍的可信度排序方案，也不能把更均衡自动解释为更正确。
