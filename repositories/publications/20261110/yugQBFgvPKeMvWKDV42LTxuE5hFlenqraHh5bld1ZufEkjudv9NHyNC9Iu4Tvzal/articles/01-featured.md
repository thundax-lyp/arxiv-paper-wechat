# arXiv Agent 与大模型研究简报｜2026-11-10｜精选

工具超时之后，怎样查明外部写入是否成功？如果给智能体配上状态机，长流程能少漏多少步？本期沿着执行、记忆与验证三条线，看看实时分叉如何节省采样资源、超长历史怎样被找回，以及图索引如何撤回文档贡献。另有研究发现，同一批污染样本混入干净数据后，反而可能让后门更容易学到。

## 智能体系统与工具使用

### 工具报超时以后，病历到底写进去了吗

MedToolFault and MedGuard: evaluating and improving clinical agent reliability

🌟🌟🌟

**问题**：工具返回的信息不可靠时，怎样同时保证证据可用、必要写入完成和病历未被错误修改？

**结论**：在原本可解的故障注入任务中，读写核验使安全完成率提高13.7至46.6个百分点，写入归因依赖单写入者与即时可见。

**新意**：用外观相同的超时复现不同提交结果，并在同一个任务契约中核对回答、必需变更和禁止变更。

一个临床智能体要根据化验结果补开检查。如果读取接口返回了一页看似完整但实际遗漏的数据，回答可能写得通顺，建议却建立在不完整证据上。到了写入阶段，另一个风险出现了。客户端等不到回执时，记录也许已经落库，也许根本没有提交。两种情况若用同一条重试策略处理，可能漏开，也可能多开。

作者把这些可能性写成六类可控故障，并为每道任务规定最终应当看到什么。评分同时看回答、必要状态变化和禁止变更。例如，复述出正确的临床建议只通过了文字这一项。工具层在读的时候沿可信分页核对患者、检查代码和记录状态。在写之前先查询已有等价记录，遇到含糊回执再查一次。恰好多出一个匹配标识时，工具层把它视作已提交。若查不到新记录，且核验成功，则最多重试一次。核验失败或出现多个候选时，提交结果仍然未决。

研究在九种配置上观察到，给原本可解的任务加入故障后，裸智能体失败率介于32.2%和67.8%。加核验后，安全完成率提高13.7至46.6个百分点。固定十二次调用上限的对照中，四种实现有三种仍改善，说明收益无法仅靠多给调用次数解释。不过，读后写归因依赖新记录立即可见且没有别的写入者。真实系统若允许异步落库或并发写入，就需要能标识提交来源的机制。另一个细节是，通用核验错误可能抹去原本帮助模型修复请求的信息，因此核验结果和原始故障线索都值得保留。

**编辑点评**：作者用有限调用预算和组件消融解释了改善来源。迟到的写入与并发写入者仍会让记录差分产生错误归因。

**为什么值得读**：这个基准给所有带写操作的智能体提供了一种故障注入办法，可以分别检查重试、状态完整性与用户收到的最终说明。

[阅读论文 PDF](https://arxiv.org/pdf/2611.09942)

### 为智能体采样实时分叉整个工作区

BunshinRL: Splitting Live Agent Workspaces for Memory-Efficient Agentic RL

🌟🌟🌟

**问题**：有状态工具调用让同一批采样占用大量内存并被慢任务拖住，能否让轨迹共享到真正分歧为止？

**结论**：在匹配训练循环的网页和桌面实验里，实时分叉使峰值内存最多降低43%，采样延迟降低23%。

**新意**：共享的不止提示或文件副本，还包括进程、通信和容器内界面，可以把工具前缀作为分叉点。

用强化学习训练能操作浏览器或桌面的智能体，需要在同一题上采样多条轨迹。它们起点相同，常常还执行了一段相同的工具调用，但每条轨迹又要有独立的工作区。直接复制容器会把暂时相同的内存付费多次，慢工具也会拖住整个批次。

作者设计的分叉机制会重建运行中的进程树和通信状态，并让分支通过写时复制共享未改动的内存页。工具前缀相同的轨迹，可以从已保存的环境快照接着跑。快照树只保存分支改动，稀疏快照之间还能从最近的保留点重放。为缩短尾部等待，系统用过去轨迹预测接下来可能出现的工具调用，在另一个工作区提前执行。如果模型随后发出匹配的调用，且依赖条件也成立，就接过已有的结果和状态。猜错时丢弃该分支，再执行真实调用。

同一套训练循环下，网页任务比一项微虚拟机分叉基线少用43%的峰值内存，桌面任务比检查点恢复基线少用30%。作者还报告，工具前缀复用及推测降低了23%的端到端采样延迟。这里的桌面图形栈也放进容器，否则窗口和剪贴板等状态可能留在外面。这个约束同样适用于远程操作。如果推测调用已经修改外部账户或数据库，丢弃工作区无法撤销那笔写入。因此可复用前缀要绑定同一初始状态，推测的权限边界也应和隔离、提交机制一起设计。

**编辑点评**：延迟收益依赖重复调用与预测命中，私有分支只有在副作用被隔离时才能安全丢弃。

**为什么值得读**：对训练基础设施而言，文章展示了如何按轨迹分歧点核算资源，以及如何为推测工具执行划定状态边界。

[阅读论文 PDF](https://arxiv.org/pdf/2611.10453)

### 把长流程的关键约束交给状态机

Keeping LLM Agents on Procedure: Executable Finite-State Control for Long-Horizon Instruction Fidelity

🌟🌟🌟

**问题**：智能体连续处理上百项事务时，怎样持续遵循开头只给过一次的流程？

**结论**：运行时闸门提高了长批次中同时正确且合规的决策数，收益随原本的流程漂移程度而变。

**新意**：在调用工具、变更状态和结束回合三个时点实施同一份流程约束，并用相同提示措辞对照提醒机制。

假设一份审核流程要求智能体逐个调查账户、记录证据、给出决策。开头几次它可能完整执行，后面为了省事开始批量读取、跳过记录，甚至在仍有账户未处理时结束。提示中再强调一次规则能让它恢复若干步骤，但长时间运行需要有办法持续知道流程走到了哪里。

论文让运行时在模型上下文之外维护一个已提交的流程状态。当前状态决定工具及参数范围。想从调查进到决策，必须让工具日志满足转移条件。尝试结束时，若工作还没完成且当前状态也不允许暂停，运行时会拦住，并告知剩余事项。账户实验中的闸门只检查有没有按要求记录、是否把不同账户交错处理，风险判定仍由模型做。作者还让对照组收到同样措辞的提示，比较提醒出现的时点和强制执行本身。

预注册的两百账户测试中，小模型在状态机帮助下平均有139项同时合规且正确，最强对照约48项。另一款基线本来就很少漂移，增加闸门后的收益较小。在困难编码子集，要求先确认根因再开放写权限的方案完成69题，对照完成62题。客户服务测试也通过状态机防止问题仍开放时直接转人工。实验显示，给运行时加约束可以守住步骤，但规格本身若遗漏边界，系统仍会忠实执行一个有缺口的流程。论文的额外任务还有1.2至3.5倍的时间或费用开销，因此收益取决于漏步的代价与原有系统的稳定性。

**编辑点评**：主证据来自一个账户流程。迁移到编码和客服时，收益伴随额外耗时或费用，业务决策能力仍需单独检验。

**为什么值得读**：对于长期运行的智能体，文章提供了一种办法来区分可由程序强制的步骤和需要模型判断的内容。

[阅读论文 PDF](https://arxiv.org/pdf/2611.10884)

## 大模型推理与规划

### 用词索引把远端历史带回注意力窗口

Retrofitting Unbounded Context onto Stock Language Models

🌟🌟🌟

**问题**：已有的语言模型能否重用窗口外的历史缓存，同时维持近处正常的顺序和推理？

**结论**：按罕见词找回历史，能在百万令牌的植入任务取回单针证据，描述式和部分两跳查询仍明显受限。

**新意**：将窗口外的原始键值放在主机，并利用位置编码的远距离性质把被选片段迁回训练范围内。

给语言模型保存很长的聊天和文档历史，难点并不只在存储。模型每生成一个词都要读注意力缓存，如果整段历史常驻显存，读写开销会随长度增长。作者尝试让现有模型维持一个真实位置的近端窗口，近端以外的键和值完整保留在主机。需要远处线索时，只迁回本次可能用得上的片段。

这么做利用了旋转位置编码的一项实测性质。近距离读取受细粒度位置影响，远处精确词面匹配主要依赖变化较慢的位置分量。片段内部顺序在生成其缓存时已经编码，因此可以搬到模型训练长度内另一个可读槽位。系统先按提问里的罕见词找片段，生成中如果出现新的定位词，还可回退缓存并重编码当前请求。模型权重保持原样，代价转成主机存储、词索引和少量重编码。

单卡试验中，两款模型在百万令牌的植入测试上读到了全部单针证据，并仅漏掉一个三键辨别样例。缓存本身仍约占130吉字节。在一个公开长文本基准上，八十亿参数模型的方案与稠密注意力相近，另一款七十亿参数模型有所退步。尤其当题目只给一段描述、没有出现原来的定位词时，远处匹配从窗口前部约95%降至0至16%。这个落差解释了为什么能在很长历史里找回一个名字，不足以说明系统能跨过同义表述或多跳关系理解那段历史。

**编辑点评**：系统结果建立在两款旋转位置编码模型上，公开长文本基准有得有失，主机内存与重编码成本要一并计算。

**为什么值得读**：它把历史有没有存下、能不能寻址、模型能否读懂分开测试，有助于为长程智能体设计更精确的记忆指标。

[阅读论文 PDF](https://arxiv.org/pdf/2611.10141)

## 检索增强生成与知识检索

### 让图检索能撤回一份文档的全部贡献

Lightfoot: Graph Retrieval-Augmented Generation with Exact, Model-Free Document Deletion

🌟🌟🌟

**问题**：从图检索中撤回一份文档后，如何确认其中产生的所有派生信息都已更新？

**结论**：在一套完整语料上，删去一成文档后的图与从剩余文档重新索引一致，过程无需再调用生成模型。

**新意**：把实体合并、事实和同义关系定义为仍然有效的分块及其提取结果的确定函数。

图检索往往先从文本里提取实体和事实，再合并别名、建边并加入摘要。这样做方便多跳查询，却使删除变复杂。一篇文档可能是某个事实的唯一来源，也可能恰好把两个实体名连接起来。只删文档和它的向量，会让图里留下已撤回的断言或过时的合并关系。

作者把索引拆成按块保存的提取结果和由这些结果确定的图。每项事实记录它由哪些文本块断言。名称只按类型和成对相似度连边，同一个实体由活跃名称的连通分量决定。删除一块材料后，原有分量可能拆开，实体标识和同义边也可能变化。因为这些派生信息的规则不依赖插入顺序，数据库可以重新计算受影响的部分。作者在含11402个段落的语料上删去一成文档，验证所得图和对余下文档从头构建的图一致。在同一删除案例里，一个对照图系统为重新生成摘要调用模型2187次，花了3.7小时。

这套约束也影响检索效果。索引成本在三套基准上都较低，但回答质量有升有降。两个不同的测试集上，对同一图检索基线，一个完全匹配率高7.7个百分点，另一个词元匹配指标低8.4个百分点。查询没有说出下一跳实体时，搜索仍容易停在较近的事实。论文验证了图的数据撤回等价性，范围是该设计的索引状态。若产品还在图外保存生成摘要或长期回答缓存，仍需分别给那些产物定义来源和删除规则。

**编辑点评**：删除等价性有明确结构前提，检索效果在不同数据上有得有失，研究没有覆盖全库社区摘要。

**为什么值得读**：索引建设者可以把重建等价当成回归测试，检验数据撤回是否覆盖了图里的间接影响。

[阅读论文 PDF](https://arxiv.org/pdf/2611.11010)

## 评测与安全

### 混入干净数据，为什么反而会强化后门

Homeopathic Learning: Diluting poisoned fine-tuning data can strengthen its effect

🌟🌟🌟

**问题**：为什么单独测试时无害的一组训练样本，混进更大的数据集后会留下触发式后门？

**结论**：匹配格式的干净数据可以强化特定污染样本的效果，结果取决于触发特征、样本比例和底座。

**新意**：将同一批污染样本放进不同数据组合，用固定总量和相同步数的对照检查后门的非单调变化。

训练数据审计常把可疑样本挑出来单独测试，希望判断它们会不会教给模型某种行为。这篇论文发现，样本是否危险有时取决于它的邻居。在一个构造实验里，污染数据与干净数据完成同一类任务，形式也相近。区别在于污染数据的输入总带同一个触发特征，而相关的异常行为埋在训练输出中。单用污染数据，模型没有在无关问题上触发异常。加入干净对照后，相同污染样本却能让触发出现。

在八十亿参数模型的一组实验里，固定五千条污染样本，逐步加入干净样本，带触发输入的德语回复率从零升至72%。把只用污染数据的训练拉长到同样的更新步数，仍未观察到德语输出。另一项试验固定三万条样本，污染比例在约三成时达到58.7%，全污染时又回到零。这意味着一次只测全污染配方，可能恰好测在不容易学习触发的端点上。

作者用简化回归解释这种现象。在污染集合中，任务格式和触发特征总一起出现，训练很难区分谁与异常输出有关。干净数据提供了同样的任务格式而没有触发，模型便更容易把剩下的差异归到触发特征。论文还在条件失调和图像分类设置中观察到类似效应。不过，每个配置的峰值都会移动，另一款模型在污染数据足够多时也能自行学到行为。这些结果适用于所测的微调设置，审计上能直接借鉴的是对同一可疑来源做不同混合比例的对照。

**编辑点评**：两种开放底座的结果表明现象可复现，现有实验主要覆盖人工构造和低秩微调，无法估计它在预训练中的普遍性。

**为什么值得读**：如果数据审计以单来源或单样本为单位，这项工作提供了一个可直接加入验收的混合训练对照。

[阅读论文 PDF](https://arxiv.org/pdf/2611.10110)
