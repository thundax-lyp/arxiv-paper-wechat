# arXiv Agent 与大模型研究简报｜2026-11-19｜精选

本期从智能体的执行循环看效率与可靠性：有限选择能否交给小模型，失败经验如何变成有适用条件的记忆，压缩历史后怎样找回证据，以及测试通过之外还该测什么。多篇论文显示，收益来自模型、流程和评估接口的共同设计，比较时需要保留各自的实验条件。

阅读推荐：🌟 值得关注；🌟🌟 建议阅读；🌟🌟🌟 优先精读。星标表示本期阅读优先级，不代表研究结论的可靠程度。

## 智能体系统与工具使用

### 先猜下一步该看哪里，再核验视觉证据

SpecLook: Speculating Where to Look for Fast and Reliable Agentic MLLMs

🌟🌟🌟

**问题**：能否先推测下一步观察的位置，减少视觉智能体反复调用工具的时间？

**结论**：在所测图像选择与物体判断任务中，先推测观察再核验，比原有循环更快，也更准确。

**新意**：把推测对象从最终答案移到可检查的观察区域，让修正围绕新增证据展开。

视觉智能体遇到小物体或高分辨率细节时，常要先思考、再调用放大工具、再读图。每一次循环都可能重新付出模型推理和图像编码成本。直接让小模型猜答案虽然便宜，却可能把自信的错误过早交给用户。作者换了一个推测对象：先猜应该看哪里。

小模型先给出一个或几个观察窗口，读过局部证据后重新作答。如果新旧答案一致且置信度足够，就结束；否则让大模型检查并修正窗口，再综合不同观察下的答案。只有证据仍弱的题需要有限的后续搜索，整个过程不再回到原先没有边界的工具循环。

在高分辨率选择题和物体存在判断上，作者用两种视觉智能体作对照。一组实验的平均准确率从百分之八十二点三升到百分之八十七点二，报告约七点七倍速度；另一组约四点七倍。消融中，拿掉观察窗口比去掉其他部件影响更大，说明收益并不只是小模型先答一次，而与获取不同证据有关。

这些数字有明确范围：题目多为选择或真假判断，答案可用首个词元概率评分，实验还使用固定硬件和批量。所谓经过认证的提前退出没有错误，只描述所测样本，不是无条件正确性保证。开放长答案、需要连续多次观察的任务，以及更长程的交互，都可能改变置信度和成本结构。对视觉智能体设计，更稳妥的启发是优先推测能被核验的观察，再决定是否值得启动昂贵推理。

**编辑点评**：证据支持这些图像任务中的效率与准确率改善；尚不能外推成一般视觉智能体的固定加速比例。

**为什么值得读**：推测系统不一定只能猜答案，也可以先猜下一步证据从哪里来，让后续核验有具体对象。

[阅读论文 PDF](https://arxiv.org/pdf/2611.23483)

### 把失败经验写成有条件的规则，再验证是否值得记住

ARISE: Practical Self-Evolving Memory for Accurate and Cost-Efficient Enterprise Agents

🌟🌟🌟

**问题**：怎样把失败经验加入企业智能体，又避免无关规则不断累积、干扰原有流程？

**结论**：有适用条件的纠正与验证门控能提高所测工作流的平均准确率，但仍会出现局部回归。

**新意**：把可检索的具体纠正与可审阅的通用规则分开维护，并分别检查是否值得进入部署上下文。

企业智能体往往在固定工具和流程中反复处理相似任务。失败之后，把整段反思永久塞进提示，既会增加成本，也可能让一次特殊情况变成普遍规则。这项研究选择只改注入上下文：基座模型、工具和工作流逻辑都保持固定，更新集中在两层记忆。

第一层是具体纠正，每条都写清楚“什么条件下，应当怎样做”，处理新任务时按相似度检索。第二层是紧凑的宏规则，由模型把一批纠正追加或重写成候选规则集。候选并不自动上线，而要在独立验证任务上超过现有规则，若连续没有改进就停止。部署时只读取已经接受的规则和相关纠正。

作者在十四个企业工作流领域、五种模型上比较。教师归因模式在两个基准的平均准确率分别提高十点九和五点八个百分点。平均调用次数减少百分之四，但总费用只下降约百分之一，因此主要价值是提高准确率，而不是已经证明显著降低总体预算。部署模型自己归因也有收益，说明不一定需要更强教师。

更细的证据同样重要。固定宏规则后移除微检索，平均准确率差距只有不到一个百分点；而微记忆准入比较使用不同任务集合，不能把它当作完全隔离的因果消融。某些模型和领域仍会退步，系统也需要可核验的成败反馈。生产中的错误记忆注入、敏感数据及规则审核，没有被这组实验解决。它提供的是一套可操作的经验治理结构，而不是让记忆无限自增长的理由。

**编辑点评**：平均收益有多模型证据，但不能忽略局部回归；验证准确率也没有覆盖权限、隐私和记忆攻击。

**为什么值得读**：可复用经验应包含适用条件，并经过版本化验证；记住一次失败与得到可靠通用规则是两件事。

[阅读论文 PDF](https://arxiv.org/pdf/2611.23588)

### 从技能里找有限决策，让小模型接手常规判断

Thinking Fast, Anywhere: One System-1 for the Decision Points of Any Agent Workflow

🌟🌟🌟

**问题**：怎样让一个小决策模型服务多种工作流，而不为每个环境手写新的委派接口？

**结论**：从技能抽取有限选择、用执行状态训练并按置信回退，可减少大模型调用；流程编译本身贡献了大量节省。

**新意**：把技能文档变成共享的决策点来源，再用同一候选评分接口连接不同工作流。

智能体每一步都调用大模型，往往把三类不同工作混在一起：已经确定的机械动作、从有限选项中判断，以及真正需要开放生成的内容。作者先把技能流程编译成这三类节点。确定动作交给代码，开放内容保留大模型，有限选择才交给小决策模型。

数据构建也围绕这个分工展开。系统多次读取技能并核对原文支持，保留真正有分支的选择；再生成能在隔离容器中运行和核验的任务，让代理执行以取得原始工具输出和中间状态。标签来自两次选项顺序相反的教师判断，只保留一致样本。最终以两万多条标签训练四十亿参数模型的候选交互指针头，用一次前向给各选项评分。

运行时，置信度不足就把判断交回大模型。论文既测试全局阈值直接迁移，也测试每工作流用五十个开发回合校准。三个未见基准和两类大模型搭配下，相对未编译代理，费用下降百分之七十五至九十一，模型调用时间下降百分之六十三至九十二。

最需要读清楚的是比较对象：即使仍由大模型完成所有语义判断，仅编译流程就已省下大量开销，还减少跳步。因此，不能把全部节省说成小模型替换带来的效果。教师一致也不代表答案必然正确，置信门槛需要验证，新流程还得具备可明确编译的结构。它的贡献更像一条工程路线：先消除不必要的生成，再把可枚举判断做成可校准、可回退的接口，而不是看到小模型便把所有步骤交给它。

**编辑点评**：离线执行数据、置信回退和未见工作流测试提供支撑；自动编译任意开放技能仍未解决。

**为什么值得读**：决策模型的价值取决于流程分工、状态质量与回退门控，可以分别测量这三个环节的贡献。

[阅读论文 PDF](https://arxiv.org/pdf/2611.23751)

### 在写代码途中反馈复杂度，比结束后统计更有用

Metrics-in-the-Loop: Complexity Feedback Reshapes Agent-Written Code

🌟🌟🌟

**问题**：测试不断通过时，怎样发现编码智能体正在累积难以维护的复杂结构？

**结论**：具体到变更函数的复杂度反馈能改善所测结构指标，但尚未证明功能正确率或长期维护成本随之提高。

**新意**：把便宜、可定位的测量放在每次改动之后，让代理在继续扩展之前修订结构。

长程编码代理容易把“测试通过”当成继续扩展的充分条件。但一个函数有多少独立分支、哪些新代码从未被测试执行，通常不会出现在通过或失败的单个信号里。等到最终交付才统计，复杂结构可能已经成为后续功能的基础。作者因此把测量接进执行循环。

每次代码变动后，宿主保存快照，检查被改函数的圈复杂度；超过阈值就列出具体函数，提醒代理将其降低。另一种干预运行代理自己的测试，指出变更行中未被执行的部分。实验把这些信号与泛泛的质量提醒分开，避免把任何额外提示都误算成测量收益。

在三类长程编码基准、四种模型上，复杂度反馈在两类任务中都显著降低复杂度集中程度。已有大工程上的效果更不稳定，部分比较区间仍包含零。单独的覆盖反馈并不必然改善结构，甚至会提高复杂度集中。功能正确性的多数比较也没有显示清楚增益。

这使论文的价值更具体：它证明代理会对运行途中可操作的结构反馈作出响应，而没有证明这些代码几年后更好维护。复杂度只是代理指标，测试覆盖也不是测试充分性；公开基准可能被训练见过，部分补充分析还是事后增加。后续如果要验证维护价值，需要让代理连续接受未知变更需求，比较修改成本和回归率。对当前系统，最实用的做法是把测量、提醒和最终质量分别记录，避免把结构分数下降包装成正确性提高。

**编辑点评**：多模型干预结果支撑结构可被引导，但结构代理指标和真实维护负担之间仍缺直接证据。

**为什么值得读**：反馈越接近当前改动、越具体可执行，越容易转化为下一步修订；同时也应警惕对单项指标过拟合。

[阅读论文 PDF](https://arxiv.org/pdf/2611.23817)

## 大模型训练与对齐

### 让各层共用词组记忆，同时保留各自的读取方式

Chorus: Shared N-gram Embeddings with Layer-wise Adaptation

🌟🌟🌟

**问题**：不同层需要不同的信息，能否共用一套词组记忆，而不为每层复制大表？

**结论**：共享表示配合逐层适配，在所测小主干上以更小的表获得更低预测损失。

**新意**：把记忆存储与各层读取方式拆开：表只查一次，各层仍按当前状态挑选和转换信息。

给语言模型加入大词组表，是用存储换计算的一条路线：遇到相邻词元组合时，只查少量条目，就能引入额外知识。但如果输入端和多个中间层各自维护一套表，相同短语的信息难以复用；直接把同一向量送给所有层，又忽略了不同深度的需要。

作者的做法是先把词元、二元词组和三元词组表示合成一个向量，再经过局部卷积细化。这个表示只计算一次。输入端和部分中间层读取它时，各自根据当前隐藏状态调整不同分量，再用独立投影变成适合本层的形式。共享的是存储，读取仍保留上下文和层次差异。

在一个两千零七十万参数主干上，十二亿表参数达到的预测损失，低于两种九十六亿表参数对照。跨数据和更大主干的三种子实验也保持优势，但最大主干仍只有一亿三千三百万参数。下游任务的平均改善较小，事实回忆收益更突出，不能据此声称推理能力全面提高。

另一项结果来自表的优化器：用行、列级统计替代逐参数动量状态后，十二亿规模表的状态内存从约四点四七吉字节降到三十五点七兆字节。这是表优化器状态的节省，并非整个训练过程的内存下降比例。对大模型训练，更关键的下一步是验证共享读取在更大主干下是否仍有效，以及查表带宽会不会成为新瓶颈。

**编辑点评**：多语料和三种子对照有支撑，但表规模曲线及部分消融只有单种子；不能直接套用到十亿级主干。

**为什么值得读**：它把条件记忆的扩容问题拆成存储、读取和优化器三个环节，便于判断真正值得优化的成本。

[阅读论文 PDF](https://arxiv.org/pdf/2611.23386)

### 让扩散语言模型学会插入和删除，修复整段错位

Beyond Replacement: Levenshtein Editing for Diffusion Language Models

🌟🌟🌟

**问题**：并行生成出现漏字或多字后，只允许逐位置替换，能否有效修复后续整段错位？

**结论**：加入插入删除及多阶段训练可提高平均成绩，并改善无置信度筛选和较大生成块下的纠错。

**新意**：在线构造可变长度编辑监督，再让后续训练阶段接触前一阶段产生的中间状态。

块扩散语言模型一次并行猜测多个位置，再逐轮细化。若只能替换某个位置的词元，漏掉一个词就会使后面许多位置一起出错；多出一个词也有类似问题。作者因此把编辑动作从替换扩展到插入和删除，让模型可以移动局部内容，而不必重写整条错位后缀。

训练时无需人工标注编辑路径。系统对当前草稿和正确答案做最长公共子序列对齐，先固定已匹配的部分，再给其余位置构造删除、插入或替换目标。它还安排多个阶段：前一阶段的输出参与构成后一阶段输入，并混入正确监督稳定训练，让模型接触推理时更可能遇到的自身错误。

在一个一百六十亿参数底座、七十四万五千条监督样本上，作者报告十二项基准平均分从五十四点八六升至五十七点一，每次前向产出的词元从六点一四增至七点零五。取消置信度筛选、一次解码全部空位时，改善更大，但该设置的平均成绩仍低于默认的置信度引导方案。更多并行选择扩大了候选解覆盖，也带来更高纠错负担。

优势并非没有边界。训练块长为三十二，测试扩到一百二十八时方法更稳，但扩到二百五十六时双方都严重退化；局部流畅的错误也可能逃过修复，甚至被继续强化。此外，每次前向产出只是并行程度，不等于墙钟速度，编辑、对齐及额外轮次仍有成本。它证明的是可变长度编辑的价值，而不是已经完成高吞吐部署验证。

**编辑点评**：同底座同数据比较有解释力，但只覆盖一个主模型，局部编辑监督也未直接优化完整修复路径。

**为什么值得读**：并行生成的错误未必只是词元选择错误，位置错位值得作为独立训练和评测对象。

[阅读论文 PDF](https://arxiv.org/pdf/2611.23750)
