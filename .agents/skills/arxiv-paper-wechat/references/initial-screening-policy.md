# 标题与摘要粗筛规范

本阶段位于 `list.json` 与 PDF 下载之间，逐篇结合 `title` 和 `abstract` 判断主要贡献对 Agent / LLM 读者的相关性。相关范围以 [editorial-policy.md](editorial-policy.md) 为准；此时不读 PDF，不做正式质量评分。

## 判断与排序

- 标题和摘要共同显示核心贡献属于 LLM / Agent 方法、系统、训练、推理、检索、协作、评测或安全时，列入相关候选。
- 纯 CV、传统机器人控制、图学习、优化、普通 NLP 或领域应用，且摘要明确没有实质 LLM / Agent 贡献时跳过。仅使用 LLM 生成数据、标注或包装应用，不自动构成相关性。
- 标题含糊时用摘要核实，不因为出现 Agent、AI 或模型缩写就保留；结合摘要仍存在合理关联但无法确定时可排在候补后部。
- 摘要缺失时先修复或刷新列表，不允许退回只看标题。
- 对所有相关候选给出唯一正整数 `relevanceRank`，越小越相关。优先主线方法贡献，其次对主线有直接价值的评测与系统，再到相邻应用；同等相关时按 arXiv ID 排序。该排序不代表全文质量评分。
- 每篇原因必须说明摘要中的具体研究对象或贡献如何关联核心范围，不用“可能相关”加原标题代替判断。

```json
[
  { "arxivId": "2609.12345", "decision": "download", "relevanceRank": 1, "reason": "摘要研究工具调用后的状态验证，直接改善智能体执行可靠性。" },
  { "arxivId": "2609.12346", "decision": "skip", "reason": "摘要的主要贡献是图像分割，语言模型仅用于生成标签。" }
]
```

输入覆盖列表每篇恰好一次。`download` 表示进入相关性排序池；CLI 实际只取未失败的前 60 篇作为当前下载候选，其余为候补。候选 PDF 经配置的有限重试仍失败时，CLI 在 `screening.downloadError` 记录原因、原子写回列表，再依相关度递补。最多取得 60 篇；候补耗尽时保留实际成功篇数并报告失败记录，不用不相关论文凑数。

已下载文件可复用，但不因已下载而提升排序。退出候选的 PDF 和 `.part` 保留，不在本 Skill 清理。转换和全文细筛仅处理最终候选；全文阅读后按重要性最多保留 40 篇。重新运行 `screening commit` 会重置下载失败记录，应仅在重新筛选或明确需要重试候选时使用。
