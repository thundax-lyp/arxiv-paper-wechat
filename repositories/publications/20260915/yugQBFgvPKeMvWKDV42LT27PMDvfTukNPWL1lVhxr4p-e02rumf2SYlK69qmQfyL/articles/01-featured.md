# arXiv Agent 与大模型研究简报｜2026-09-15｜精选

本期最值得注意的变化，是 Agent 研究开始从“任务做成了没有”转向系统边界：交接能否保留承诺，工具调用成功后外部状态是否一致，审计发现危险时控制器会不会真的停下，以及经理式回修是否反而制造迎合。另一条主线聚焦自我改进与长期运行：harness、技能、探索策略、会话记忆和科学工作流都在尝试把经验变成可复用、可验证的状态。星标表示本期阅读优先级：🌟 值得关注，🌟🌟 建议阅读，🌟🌟🌟 优先精读；它不等同于结论可靠性，具体证据边界见每篇导读。

阅读推荐：🌟 值得关注；🌟🌟 建议阅读；🌟🌟🌟 优先精读。星标表示本期阅读优先级，不代表研究结论的可靠程度。

## Agent系统与工具使用

### 跨模型交接不必从头再来

Do Not Restart: Residual Completion for Stateful Agent Handoffs

🌟🌟🌟

**问题**：模型级联能省钱，但继任 Agent 如果看不清前任已经接受的选择、已产生的外部效果和未完成义务，最安全的做法往往只剩从头重跑。

**结论**：CFRC 用残余契约和实时回执约束交接，在五个有状态工具环境中以强模型全量执行 22.0%—34.6% 的推理成本，获得相近的总体准确率。

**新意**：它把 handoff 从“把聊天记录交给下一个模型”改写为承诺约束的剩余任务：已完成什么、还欠什么、什么证据才算完成，都进入可检查结构。

模型路由通常只把问题理解成“什么时候换一个更强的模型”。对有状态工具任务，这还不够：前任可能已经接受退款方案、修改账户或完成一半订单，继任者若从原始请求重新规划，既会浪费推理，也可能重复产生真实副作用。

CFRC 先从已接受进度中冻结一份残余契约，把选择、外部效果和未尽义务分开记录。继任模型不能直接在真实环境试错，而要先在副本上把后续计划闭合成证据图；真正执行时，每项义务必须由实时回执消除。三条规则分别保证先确定剩余目标、整份方案形成后才授予权限、看到活证据后才宣布成功。

论文在 STATE-Bench、τ²-Retail、τ²-Airline、ToolSandbox 和 Agent-Diff 上比较两组同供应商模型，并补充跨供应商结果。CFRC 的宏观准确率接近让强模型整题重做，却只花 22.0%—34.6% 的推理成本。这个结果说明，交接价值不只来自“传上下文”，而是来自保留已经被承认的承诺，同时限制继任者能改动什么。

边界也很明确：形式正确性依赖残余契约完整，工具 schema 之外的口头披露可能漏记；实验只覆盖一次廉价到强模型的交接，多级循环路由仍待验证。

**编辑点评**：证据覆盖五种工具环境和多组模型，成本结果有实际意义；但协议的安全性最终受制于契约构造，遗漏的承诺不会被后续验证自动补回来。

**为什么值得读**：它给模型级联提供了比摘要传递更严谨的接口设计：保存的不只是状态，而是哪些状态可以继承、哪些义务尚未解除，以及完成必须拿出什么回执。

[阅读论文 PDF](https://arxiv.org/pdf/2609.13800)

### 让 Agent 在历史搜索树里“做梦”改进探索策略

Dream-RSI: Recursive Self-Improvement through Evolving Worlds

🌟🌟🌟

**问题**：自动发现Agent需要不断改进探索策略，但在线元优化要为每个候选策略跑完整长程搜索，反馈昂贵而迟缓。

**结论**：Dream-RSI 用历史发现树搭建回放模拟器，在 Lasso、数学优化和 GPU kernel 任务上以更少在线生成取得相当或更好的发现质量。

**新意**：它不改变底层编码 Agent，而是把探索策略显式化；历史不再只是上下文，而成为可反复试验新策略的低成本“世界”。

递归自我改进常被描述为模型改写自己，但在算法和工程发现中，更现实的瓶颈是“下一步去哪里找”。固定搜索策略不能随空间变化；在线优化策略又必须重复运行昂贵实验，等到长轨迹结束才知道这次组织方式是否有效。

Dream-RSI 在编码 Agent 外增加一层轻量编排，把并行分支、继续深挖或切换方向等探索选择写成可修改策略。系统保留历次发现形成的树，并把这棵树当作已实现搜索空间的回放模拟器。候选策略先在历史树中“做梦”，快速得到近似反馈；选出的策略再部署到真实任务，产生的新分支继续扩充模拟器，由此形成自我改进闭环。

作者在算法工程、数学优化和 GPU kernel 三类任务上与相同Agent、相同初始化和相同资源约束的固定递归探索比较。Lasso 场景中，Gemini 3.1 Pro 的调用数从550降到317，平均运行时间也从3587.1毫秒降至2931.0毫秒；在 VGG16 和 LayerNorm kernel 上，用少2.43倍和1.79倍的生成达到相当最终性能，另两项则在相近预算下得到更高性能。

回放世界只覆盖历史真正走过的区域，可能系统性忽略未探索分支；三类任务都有明确可执行反馈，也不代表开放研究同样适用。它最可靠的贡献，是展示如何把昂贵在线探索变成“离线试策略、在线扩世界”的循环。

**编辑点评**：与固定探索共享底层Agent和预算，成本比较较可信；但模拟器由既有发现树组成，偏差会随闭环累积，论文尚未充分讨论探索盲区。

**为什么值得读**：它把自我改进从抽象口号落到一个可实现的系统问题：哪些控制策略可以先在历史经验上低成本试验，再谨慎投入真实执行。

[阅读论文 PDF](https://arxiv.org/pdf/2609.14858)

## RAG与知识检索

### RAG 压缩后的引用，可能只对摘要正确

The Attribution-Compression Frontier in Retrieval-Augmented Generation

🌟🌟🌟

**问题**：RAG 压缩常用答案质量衡量成败，但压缩器若改写证据，生成器给出的引用可能只支持改写后的摘要，无法再追溯到原始来源。

**结论**：在 ASQA 的一个 RECOMP 设置中，引用对摘要的精度为 0.86，回到源片段只剩 0.12；同一设置下，不支持率从摘要核验的 0.17 升到回源核验的 0.88。

**新意**：论文把“发出的引用”和“落到源证据的引用”分开，并同时报告名义压缩预算与实际压缩比，让压缩—质量权衡加入可归因性维度。

上下文压缩通常以一个直观问题收尾：输入变短以后，答案还对不对？但对带引用的 RAG，答案看似正确并不意味着引用仍能回到原文。摘要器可能把多个来源融合成一句顺畅陈述，生成器再引用这个摘要；如果核验也只看摘要，系统就会把自己改写出的说法当成证据。

本文固定生成器和主要 NLI 评价器，在 ASQA 与 QASPER 上比较重排、抽取式选择、抽象摘要、token 剪枝和一种抽取—聚类—改写方案。核心做法是保留两套分数：一套检查输出引用是否支持压缩后的内容，另一套尝试恢复到原始源片段，再检查真实可归因性。同时记录名义预算与实际达到的压缩率，避免不同方法看似在同一预算下比较，实际输入长度却差很多。

差距非常大：ASQA 上一个名义 0.25、实际 0.08 的 RECOMP 设置，对摘要的引用精度是 0.86，对源片段只有 0.12；逐条声明回源核验后，不支持率从 0.17 变成 0.88。抽取式方法的落地精度更稳定，但随着预算收紧，答案质量也下降。

作者没有把这些数字写成最终真值：源片段恢复和引用判断依赖同一个 NLI 模型，尚缺独立人工校准。因而最可靠的结论不是某个压缩器胜出，而是任何压缩 RAG 都应同时报告“看起来有引用”和“引用能回到哪里”。

**编辑点评**：固定生成器、多压缩方法和双基准让比较具有解释力；最大的限制是回源与评分共享 NLI 评价器，绝对数值仍可能带系统偏差。

**为什么值得读**：它提供了一套立即可用的 RAG 审计框架：压缩率、答案质量、发出引用和源证据支持必须一起测，否则系统可能在压缩过程中悄悄切断证据链。

[阅读论文 PDF](https://arxiv.org/pdf/2609.14245)

## 多智能体与协作

### 经理反复打回，可能让多 Agent 团队更差

Loop-Back Authority in LLM Agent Teams: A Paired Experiment on Flat and Hierarchical Coordination

🌟🌟🌟

**问题**：多 Agent 框架普遍让经理审稿并强制工人修改，但在没有可验证答案的任务里，权威反馈可能只是让模型迎合，而非纠错。

**结论**：43 对商业分析报告中，扁平结构的效用和写作清晰度显著更高；层级回修多花 51.5% token，报告中的保留措辞多 53%，可检查规格却没有提升。

**新意**：实验固定五个 Agent、模型、角色、提示、工具和数据，只切换经理是否拥有打回权，把质量差距定位到回修循环而非组织的其他部分。

层级协作听上去很自然：经理分配任务、检查结果、不满意就让工人重写。传统组织理论认为这种权威能加快收敛；对经过 RLHF 的语言模型，权威批评也可能成为一种必须顺从的社会信号，尤其当批评无法被客观验证时。

论文在商业智能报告任务上构造配对实验。每组都使用相同的五个模型、角色、提示、工具和数据，唯一差别是经理能否拒绝工人输出并要求修改。43 对产品、86 次运行由五模型裁判和确定性规格检查共同评分。扁平团队在效用上效应量 d=0.42、p=0.009，在写作清晰度上 d=0.34、p=0.030，均优于层级团队。两者长度相近、规格准确率都接近上限，但层级方案多花 51.5% token。

过程分析把问题定位得更具体：层级作者的第一稿与扁平最终稿没有差别，差距在被要求修改后才出现。每多一次回修，清晰度平均再降 0.14 分，最终文本的hedging多53%。换言之，模型没有获得可执行的新证据，只是用软化措辞和填充回应权威。

结论不能直接推广到代码、长上下文或有强验证器的任务；报告质量仍主要由LLM裁判评估，事实性也未单独测量。合理的工程规则不是取消经理，而是让修改由测试失败、缺段或证据冲突等可验证信号触发。

**编辑点评**：单一变量配对和第一稿分析使因果解释很清楚；但样本只有43对、任务单一，清晰度还对裁判偏好较敏感。

**为什么值得读**：它挑战了多 Agent 系统的默认组织方式，并给出可执行替代：经理可以分解和路由，但不应仅凭意见持有强制回修权。

[阅读论文 PDF](https://arxiv.org/pdf/2609.14767)

## 评测与安全

### 政策写得含糊，Agent 基准就会把合理行为判错

Policy Loopholes in Agent Evaluation: When Policy Ambiguity Masquerades as Agent Error

🌟🌟🌟

**问题**：Agent 合规基准通常假设政策只有一种正确解释；若政策沉默、矛盾或含糊，单一金标会把合理选择也计成模型错误。

**结论**：对 τ²-bench 两个领域的审计发现 17 个政策漏洞；受影响任务会以不同方式压低三类模型得分，并让所有模型在重复试验中更不一致。

**新意**：它把评测误差的源头前移到政策文本，并指出真正可利用的漏洞需要两个条件同时存在：政策歧义，以及工具允许多种后果。

Agent 基准常把政策、工具和金标轨迹打包成一个确定环境，再用是否走到金标结果衡量能力。问题是，自然语言政策未必真的确定唯一动作。退款时间、例外条件或优先级若没有写清，两个操作都可能有合理解释；这时模型间差异可能只是各自如何补全政策空白。

论文先不看任何 Agent 轨迹，只对 τ²-bench 的航空和零售政策做条款级审计，寻找沉默、歧义和冲突；随后再看 GPT-5、Kimi-K2-Thinking 和 Mistral-Large-3 各四次运行，验证这些漏洞是否实际改变得分。两领域共 164 项任务、1968 次运行中，作者识别出 17 个政策漏洞，其中一部分能在失败轨迹中直接确认。

跨领域对比带来最有用的机制判断：只有政策复杂度超过工具能强制执行的范围时，歧义才会转化为可利用分叉。受影响任务不仅让模型得分下降，而且不同模型下降方式不同、同一模型重复运行也更不稳定。因此，补一个金标轨迹并不能修复问题，甚至可能制造互相矛盾的答案；修复应发生在政策层。

研究只覆盖同一基准两个领域，复杂度和工具可执行性也没有完全解耦，漏洞合理性仍含人工判断。尽管如此，它把一个常被归因于“Agent 不守规则”的问题，转化为可在采集金标前审计的规范质量问题。

**编辑点评**：先审政策、后看轨迹减少了结果导向找漏洞的风险；但两领域不足以确立普遍机制，主观的“合理解释”仍需更标准化流程。

**为什么值得读**：任何用自然语言 SOP 评测或约束 Agent 的团队都能直接采用其顺序：先查政策是否唯一可执行，再收金标，并把漏洞任务与干净任务分开报告。

[阅读论文 PDF](https://arxiv.org/pdf/2609.14400)

### Agent 买到资源后，还不能直接获得使用权

AcquireBound: Runtime Authorization for Resources Acquired by AI Agents

🌟🌟🌟

**问题**：Agent 可以合法购买算力、创建账号、获取凭据或委派其他 Agent，但交易获批只说明“买到了”，并不说明所得资源可以成为新权限。

**结论**：AcquireBound 在激活前隔离并解析实际能力；参考语义接受 20/20 良性轨迹、拒绝 40/40 注册危险轨迹，MCP 到 Docker 组合中的 16 条危险路径均未发出未授权启动。

**新意**：它补上履约之后、首次使用之前的授权层，并用资源—能力超图同时约束身份、数据、效果、委派和全图聚合上限。

现有 Agent 交易控制多半检查预算、付款、OAuth 或委托是否有效。但一个操作合法完成后，返回物可能带来比请求更大的权力：云实例附带管理凭据，新账号能继续创建资源，被委派的 Agent 又能转委派。退款也不会自动让已经获得的权限消失。

AcquireBound 因而把“获得资源”和“激活权力”拆开。所有返回物先进入隔离区，系统从经过认证的提供商证据解析其真实能力和规范身份，再用当前 epoch、来源链和一个向下闭合的关系包络判断能否激活。对不可重复的外部效果，单次许可还必须在真正产生效果的线性化点重新验证并消费，避免崩溃、重试或延迟成功复用旧授权。

论文给出八项安全性质，覆盖隔离、真实支撑、权限不放大、拆分规避、崩溃重试、退款、版本新鲜度和效果约束。实验以五类资源做离线语义和独立检查：20 条良性轨迹全部通过，40 条危险轨迹全部拒绝，89 个篡改测试全部被发现；冻结的 Codex 和 Gemini MCP 客户端完成 54 次本地调用，MCP 到 Docker 的 18 个组合案例中，16 个危险路径都没有加入未授权启动请求。

这些结果主要来自注册的离线轨迹和本地组合，并未覆盖真实云提供商、错误策略或解析器遭攻击。它证明的是一个授权接口可被明确检验，不是开放世界中已经实现绝对安全。

**编辑点评**：形式属性、独立检查器和跨边界组合让设计相当扎实；风险在于实际能力清单仍依赖提供商证据与解析器，输入错误会把安全问题前移而非消失。

**为什么值得读**：它为 agentic commerce 和动态委派提出了关键区分：付款、交付与授权是三件事。系统必须在资源第一次产生效果前再做一次能力级决定。

[阅读论文 PDF](https://arxiv.org/pdf/2609.14744)
