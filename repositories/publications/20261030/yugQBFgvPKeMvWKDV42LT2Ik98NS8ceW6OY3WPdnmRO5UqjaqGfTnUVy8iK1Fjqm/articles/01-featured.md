# arXiv Agent 与大模型研究简报｜2026-10-30｜精选

本期关注智能体如何把证据变成可靠行动：网页环境怎样复建，反馈怎样改变重试与模型选择，指令与数据如何分离，以及形式证明能核验到哪里。另有技能复用、多智能体成本和科研评测工作，尤其值得留意高分、共识与真实可靠性之间的距离。

阅读推荐：🌟 值得关注；🌟🌟 建议阅读；🌟🌟🌟 优先精读。星标表示本期阅读优先级，不代表研究结论的可靠程度。

## 智能体系统与工具使用

### 把真实网站变成可复位的智能体训练环境

WebAnything: From the Wild Web to Scalable Agent Environments

🌟🌟🌟

**问题**：怎样把只能在线浏览的网站，变成可复位、可验证、可持续生成任务的训练环境？

**结论**：浏览器证据驱动的重建能扩展到244个站点，并支持提升外部网页任务成绩；跨站维护能力仍未被证明。

**新意**：让探索、构建与独立验证分工，用行为和状态证据指导局部修复，而非只追求页面外观相似。

网页训练的难点不仅是页面多，而是操作后状态必须正确、任务必须能重放。直接在真实站点训练，会受到账号、网络与内容变化影响；手工复制站点又难扩展。作者提出先由探索器记录浏览器可见的结构、资源和交互，再让构建器复现环境。

关键环节是把验证器独立出来。它依据探索阶段的证据检查任务与状态，在一轮检查中冻结待验版本，再要求构建器局部修复；若证据不足，则回到真实站点定向补采。这种循环把“看起来像”推进到“指定操作后是否到达预期状态”，但覆盖仍取决于探索到的路径。

论文报告构建244个站点，覆盖14个领域、53个类别，并得到12984个通过验证的任务。以其中5856条轨迹微调90亿参数模型后，三个外部网页评测分别改善9.9个百分点、约6个百分点和13.33个百分点，说明训练价值不只体现在自建环境内。环境质量的盲审则集中在五个对照网站的14个状态，得到12胜2平，证据范围明显小于整个站点集。

因此，这是一条值得复用的环境制造路线，而非已经解决网页镜像维护。站点改版、长尾交互、账户状态和更复杂业务约束是否能持续可靠重建，还需要后续独立验证。

**编辑点评**：独立验证和定向补采比一次性生成页面更有工程价值。外部评测迁移是积极信号，但不能用小规模状态审查替代全部环境的行为保真证明。

**为什么值得读**：适合建设网页智能体训练与回归环境的团队，重点读证据记录、状态验证及修复闭环。

[阅读论文 PDF](https://arxiv.org/pdf/2610.37786)

### 证明智能体接近旧基准饱和，真实代码义务仍难

Scaling Lean Theorem Proving for Real-World Code Verification

🌟🌟🌟

**问题**：数学证明智能体的高成功率，能否迁移到带真实程序结构的验证义务？

**结论**：旧数学题已接近饱和，而新程序基准在每题30分钟预算下仅证明52.7%，验证难点仍在。

**新意**：以隔离上下文的递归证明搜索连接并行尝试，并用独立内核核验固定命题，另建真实代码导出的基准。

形式证明给智能体提供了少见的强反馈：候选证明能否通过检查器，有明确答案。但若系统为了通过而改写命题、增加不可靠公理，或者题目已被训练记住，高成功率仍会被误读。作者因此固定命题签名、限制允许的依赖，并把反例与证明输出分开处理。

证明系统递归拆分子目标，让代理在相互隔离的上下文中搜索，结合异步与并行策略尝试，再交给证明内核检查。它在一个旧竞赛数学集合完成672题中的669题，也报告解出2026年国际数学奥林匹克全部六题。由于模型训练截止与题目污染无法被完全确认，这些成绩不能单独证明陌生问题上的同等推理能力。

论文更有区分力的部分，是从真实安全编程语言代码导出形式化验证义务：2045组代码与规格形成11533条义务。在抽样2000条、每题30分钟的实验中，系统证明1054条，即52.7%。新基准把关注点从熟悉竞赛数学转向实际程序结构，也暴露出旧题近乎满分之后仍有很大缺口。

这些结果不依赖新训练一个专用大模型。不过，内核通过只保证给定形式命题在允许假设下成立；若规格遗漏真实要求，或者自然语言意图被错误翻译，证明仍不能兜底。阅读时应把证明搜索能力、形式规格质量和软件实际正确性分开判断。

**编辑点评**：独立内核检查把生成答案变成了可审计证据，但规格入口仍是人机系统中的薄弱处。新基准比单看旧题满分更能帮助识别真实验证的剩余工作。

**为什么值得读**：适合关注证明智能体、代码验证和可靠工具链的读者，重点看任务固定、允许公理及未证出义务的构成。

[阅读论文 PDF](https://arxiv.org/pdf/2610.38174)

## 大模型训练与对齐

### 把指令与数据分开，能学到多强的防注入边界

Post-Training Large Language Models with LLMON

🌟🌟🌟

**问题**：当指令和工具数据共享文本通道时，能否通过训练让模型学会稳定区分两者？

**结论**：结构化标记加后训练显著降低同族模型的间接注入成功率，但有上下文开销及部分能力回退。

**新意**：将数据、指令与系统段显式分型，并以引用指定可执行对象，把权限语义纳入训练分布。

网页与工具返回值里可能含有“忽略此前要求”之类文本。若模型只按自然语言语气判断指令权重，攻击者就能让数据看起来像命令。作者设计了一套带类型和编号的结构化表示：不同来源被放入不同段落，执行要求必须明确引用相应对象，模型据此学习哪些内容可以影响行为。

方法并不只是在提示前加一段说明。作者构造约440万条结构化样本、46亿令牌，并在同族30亿参数与80亿参数模型上进行监督和强化训练。报告中的间接注入成功率从53%至100%的区间，降到0.02%至5.6%。这说明显式表示与针对性训练结合，有可能减少来源混淆。

代价也很清楚。标记使上下文增加约7%至15%；80亿参数模型在六项能力的平均成绩从74.2降到72.8，数学项从84.1降到79.6，而30亿参数平均值大体持平。直接攻击和多轮攻击下的稳健性仍明显较弱，不能把间接注入上的改善推广到全部攻击形式。

更关键的是，这仍是模型学得的行为边界，不是外部执行器强制的权限隔离。实验只覆盖一条模型家族，跨模型迁移和面对适应性攻击时的效果仍需确认。对于部署，这种方法更适合作为来源标记与外部工具授权之间的一层防护，而不是授权系统的替代品。

**编辑点评**：来源类型有明确语义，比单纯要求模型“不要被注入”更可操作。但能力损失、输入长度以及直接攻击弱点必须一起看，不能只展示最漂亮的攻击成功率下降。

**为什么值得读**：适合研究指令层级、工具协议和抗注入训练的读者，尤其值得比较表示设计与外部权限检查各自负责的边界。

[阅读论文 PDF](https://arxiv.org/pdf/2610.38120)

## 评测与安全

### 看到注入文本，不等于将要执行危险动作

Exposure Is Not Commitment: Double-Stratified Evaluation of Latent Monitors for Tool-Using Agents

🌟🌟🌟

**问题**：如何区分安全监控器认出注入文本，还是预见智能体真的会采取危险行动？

**结论**：控制文本暴露后，行动前探针仍有预测力，但在一组实验中未超过文本基线，离可靠防御还有距离。

**新意**：把暴露与执行承诺分别分层，避免把识别攻击文本的能力误算成识别危险行动的能力。

智能体读到带攻击指令的工具结果后，可能拒绝，也可能照做。若安全监控实验把未读到攻击的正常轨迹与读到攻击的失败轨迹混在一起，分类器只要认出攻击文本就能得高分，测到的并不是实践中最关心的“下一步会不会越界”。

作者据此拆开两个变量：是否接触攻击，以及接触后是否转向危险行动。训练和测试以任务分组，既比较混合样本，也只在已经暴露的轨迹内作判断，并把行动前的内部表示与可见文本基线放到一起。以工具使用环境中的一组模型为例，控制暴露后，逻辑探针的曲线下面积为0.853，文本基线为0.855；另两类开放模型的相应探针结果为0.896和0.912。内部表示仍含信息，但不能只凭原始高分主张它具有独特优势。

研究还关注作出动作前后不同位置的读出。然而轨迹较短，主要只能考察有限的提前步数；完整内部表示也仅对开放模型可得。论文没有证明这种监控器已经能在在线交互中稳定阻断攻击，更没有覆盖会适应防御的攻击者。它最可靠的贡献，是给安全监控评测提出一个必须控制的混杂因素。

**编辑点评**：分组切分和暴露内对照，让结论比单一检测分数更有解释力。下一步仍需把误报、漏报与真实阻断代价接起来，才知道能否用于运行中的系统。

**为什么值得读**：适合设计提示注入监控、内部表示探针或安全评测的读者：先检查实验究竟在预测哪件事。

[阅读论文 PDF](https://arxiv.org/pdf/2610.37679)

### 有反馈的重试，应该怎样评测

Seq@K: Evaluating Language Models Under Sequential Feedback

🌟🌟🌟

**问题**：模型在一次失败后能否利用反馈，与独立多抽几次相比，会改变怎样的选择结论？

**结论**：顺序反馈会改变模型排序和成本前沿，收益同时取决于反馈内容与历史组织方式。

**新意**：把有限尝试预算下的序列交互作为评测对象，显式区分重采样和带反馈修正。

常见的多次采样评测把每次回答视为独立尝试，只要有一次成功就算完成。但真实智能体通常会看到执行失败、测试报错或审查意见，再继续修改。擅长独立作答的模型，未必最会吸收这些反馈，两种能力不应由同一个分数代替。

作者在七类基准、16个模型上比较两种协议。顺序协议把前次尝试及反馈带入下一轮，记录限定次数内是否解决任务，并同时观察成本。结果显示，模型相对排序和成本最优前沿均可能变化。在一个包含30个任务、七个执行模型的复杂指令实验中，某模型从独立尝试时靠后，变成顺序反馈下并列领先；这个例子说明排名依赖交互条件，而不是给出了一个普遍最优模型。

反馈本身也是实验变量。批评者是否知道评分标准、反馈包含多少可执行信息、过去尝试是否完整保留，都会影响收益。由更强批评者直接透露解决路径得到的提升，不能简单解释为执行模型自身纠错能力更强。相同尝试次数也不代表相同计算量，每轮输入变长、批评调用和输出长度都可能增加成本。

对选型而言，论文的实用建议是把实际产品的反馈环搬进测试，并一并固定反馈来源与历史策略。独立采样成绩仍有价值，但不能单独预测一个持续修改的系统会怎样工作。

**编辑点评**：这是对评测对象的一次有用修正。若要据此比较投入产出，还应报告执行模型与批评者的总成本，避免把额外监督带来的收益全部记到模型名下。

**为什么值得读**：适合做编程、工具调用和迭代写作智能体选型的读者，帮助把离线榜单改造成产品实际会经历的测试。

[阅读论文 PDF](https://arxiv.org/pdf/2610.37859)

### 不读解释也能得高分：自动可解释性评测的结构捷径

Scoring Explanations Without Reading Them: Structural Shortcuts in Automated-Interpretability Evaluation Data

🌟🌟🌟

**问题**：自动解释评测的高分，到底来自读懂特征解释，还是来自数据窗口和标记方式？

**结论**：只看位置与标记的简单规则即可在存储数据上超过原裁判；干净窗口对照支持结构捷径这一解释。

**新意**：先建立完全不读解释的基线，再更换窗口构造与标记分布，检验评测是否依赖无关结构。

自动可解释性常让语言模型根据一段文字解释，判断哪些词元会激活某个特征。若判断准确，就据此认为解释质量好。但输入窗口如何截取、激活位置如何标记，也可能泄露答案，导致裁判根本不必理解解释。

作者对一个模型的500个稀疏特征展开审计。在存储评测数据中，只利用中心标记位置的简单规则，平衡准确率达到0.979，而原来存储的语言模型裁判结果为0.838；仅统计标记数量也能达到0.969。如此强的无解释基线，说明这个数据集上的高分不能直接归功于语义理解。

随后作者改变对照条件。在随机偏移的自然窗口中，固定位置先验与目标的相关仅0.015，而一种利用解释文本的方法在49个特征上仍得到0.331相关，打乱解释后则降至0.013。这一组对照说明：结构捷径被削弱时，解释本身仍可能提供有效信息，不能由前面的审计推导出“自动解释完全无用”。

局限在于，存储标记包含重建步骤，匹配标记分布的更严格实验尚未完成；作者也没有直接证明全部特征的相对排名因此受损。因此最稳妥的结论是评测构造需要压力测试。今后报告解释质量时，应加入不读解释的基线、打乱解释对照和自然窗口，而不只比较复杂裁判之间的分数。

**编辑点评**：文章把怀疑落在可计算的无解释基线上，证据链比较清楚。需要保留的边界是：已发现得分捷径，不等于已量化所有下游研究结论受影响的程度。

**为什么值得读**：适合做自动可解释性、裁判评测和数据集设计的读者，也提供了一个可迁移的审计问题：去掉本应关键的信息，系统还能拿多少分？

[阅读论文 PDF](https://arxiv.org/pdf/2610.37676)
