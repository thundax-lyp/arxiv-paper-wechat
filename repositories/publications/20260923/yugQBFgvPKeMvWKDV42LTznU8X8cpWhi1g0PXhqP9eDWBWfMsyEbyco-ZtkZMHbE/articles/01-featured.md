# arXiv Agent 与大模型研究简报｜2026-09-23｜精选

本期关注智能体如何把失败经验沉淀为可靠的执行框架，以及记忆、协作和检索系统如何判断证据与状态。几篇实验也提醒我们：一致、快速或得分更高，未必意味着判断更正确。

阅读推荐：🌟 值得关注；🌟🌟 建议阅读；🌟🌟🌟 优先精读。星标表示本期阅读优先级，不代表研究结论的可靠程度。

## 智能体系统与工具使用

### 科研智能体能否持续改进自己

Recursive self-improvement of AI research agents

🌟🌟🌟

**问题**：智能体能否把提高自身研发效率作为下一轮研究对象？

**结论**：一次八天运行接受七次执行框架改写，在四个留出基准上达到或超过强人工框架；持续递归的稳定性仍未知。

**新意**：将解决研发任务的内层搜索，与改写研究智能体自身代码的外层搜索连成闭环。

研究的关键是把“自我改进”具体化为可运行、可比较的代码变化。内层智能体在固定预算下改进机器学习、算法或工程任务；外层智能体修改这个研究流程的搜索、记忆与验证逻辑。候选版本不能只在自己看过的任务上得高分，而要通过隐藏评分筛选。这样，每次接受的改写都成为下一轮的起点，模型权重本身并未变化。八天里系统保留七次连续改进，最终版本在四项未参与筛选的基准上达到或超过一套长期人工开发的强框架；另一个留出任务族里的奖励作弊率也从百分之五十五降到三十二。这个结果说明，框架设计本身可以成为有效的研究对象，也说明隐藏评测能在一定程度上制约只会刷分的改写。但论文只有一次长程运行，外层再递归时的收益受噪声和成本影响，不能据此推断改进会无限持续。

**编辑点评**：留出基准和固定预算增强了结论可信度；单次运行及后续递归的高成本限制了长期外推。

**为什么值得读**：可借鉴的是把智能体框架改写、独立评测和回滚选择做成一个明确的实验闭环。

[阅读论文 PDF](https://arxiv.org/pdf/2609.26457)

### 让智能体把反复使用的策略写成程序

Grow the Harness, Not the Context: From Strategy-Free Scaffolds to Reusable Specialist Agents

🌟🌟🌟

**问题**：相似任务反复出现时，控制流程为何还要每次由模型重新想一遍？

**结论**：让执行框架从任务反馈中长出可复用程序，在多数组合中成功率更高且模型调用大幅减少；结论主要来自网页任务。

**新意**：从没有任务策略的脚手架起步，以失败轨迹定位函数级改动，再用留出任务阻止退步。

许多智能体把计划、重试与工具调用顺序都塞进当前上下文，任务一结束就丢掉。本文反过来把这些重复控制决策沉淀为执行框架的代码。系统从只暴露模型与工具接口的空白脚手架开始；任务失败后，函数级执行轨迹缩小可修改范围，优化器针对一组失败共同修复。候选改动还要通过留出任务门槛，若伤害既有能力便回滚。被接受的代码长期积累，模型仍负责每个新任务的语义判断。作者在两个网页任务基准和三档模型上比较：六组组合中五组平均成功率最高，模型调用下降约百分之七十六至九十二。尤其小模型在网页任务中的表现不再随规模明显塌陷，显示框架能承担部分原本由模型临场推理完成的工作。不过，实验集中于网页浏览与交互；长期代码增长会怎样影响维护、安全和跨任务族迁移，论文没有给出同等强度的证据。

**编辑点评**：多模型与消融支持组件贡献，但框架长期演化后的维护和安全成本仍缺少实测。

**为什么值得读**：对频繁执行同类任务的系统，值得测试哪些控制规则可以安全地变成可回滚程序。

[阅读论文 PDF](https://arxiv.org/pdf/2609.26760)

### 智能体技能变成习惯后，错误也会稳定重复

Making Agents More Consistent: Skills Should Form Habits for Repeat Tasks

🌟🌟🌟

**问题**：把重复工作写成技能，怎样避免把偶然错误也写死？

**结论**：技能使重复派发高度一致并节省标记，但范围守卫在边界输入上误放行约四分之一。

**新意**：把技能视为有适用区域的候选程序，经多级门槛竞争上岗，范围外退回模型推理。

可复用技能常被描述为节省上下文的捷径，本文把“何时让技能接手”作为核心问题。智能体从自身轨迹里挖掘确定性脚本，为每个脚本声明适用的输入区域，并通过逐级加严的测试门槛；关键门槛把候选执行轨迹与保留的参考轨迹比较，容差来自参考自身的运行波动。在文本转查询实验中，几个纯推理配置对同一批问题重复作答时经常不一致，而习惯化版本的四百五十六次重复派发保持一致，也降低标记消耗。但确定性同样会稳定地复现错误：范围守卫在自然改写输入上误放行百分之二点六，在边界附近升至百分之二十六；多数此类失败无法被轨迹一致性门槛察觉。研究因此不只是节省调用次数，更提出技能可靠性要分开检验适用范围、执行一致性与答案正确性。

**编辑点评**：重复性证据扎实，范围守卫的静默错误却是部署时的主要边界。

**为什么值得读**：评估技能系统时应专门设计边界输入测试，不能把结果稳定当成结果正确。

[阅读论文 PDF](https://arxiv.org/pdf/2609.25299)

### 运行时策略能否让智能体稳定交付

FIRE: Failure-Informed Runtime Engineering for Reliable Language-Model Agents

🌟🌟🌟

**问题**：智能体已经有能力解题，为何重复运行仍交付失败？

**结论**：针对失败状态的运行时策略提高双次成功率，随机对照优于通用复核和假策略；跨任务迁移仍待验证。

**新意**：把失败前状态与具体动作约束绑定，在执行时触发，而不是重新训练模型。

只看一次能否做对，会掩盖智能体偶尔找到解法却反复交付失败的问题。本文从失败轨迹中提取针对性的运行时策略：某些状态给出明确自然语言提醒，某些动作直接拒绝。策略由执行框架施加，模型权重和用户提示不变。在完整的八十七项终端任务集上，强模型连续两次成功的比例由百分之六十四点四升至七十三点六，而两次中至少一次成功的比例只小幅变化。这表明收益更多来自把可达到的能力稳定交付，而非突然获得新能力。作者还设置了时间相同但内容无关的假策略、通用验证提醒和重新考虑等随机对照；真实策略在适用任务上的成功率为百分之六十一，无策略为百分之三十九，假策略为百分之三十六。结果支持针对性策略的机制，但这些策略来自已有失败，面对全新任务是否仍有效尚不能直接推断。

**编辑点评**：完整任务集和随机对照较强；策略的来源决定了新任务迁移需要单独评估。

**为什么值得读**：它提示系统工程师先审视失败时机与动作约束，再考虑增加模型能力或泛化提示。

[阅读论文 PDF](https://arxiv.org/pdf/2609.26048)

### 判断代码记忆失效，要问具体主张

Impact Is Not Invalidation: Ask About the Claim, Not the Diff

🌟🌟🌟

**问题**：仓库变更后，哪些记忆主张真的失效了？

**结论**：询问具体主张是否仍成立，比笼统判断代码差异是否改变行为准确得多；真值主要来自可执行测试。

**新意**：把记忆有效性判断绑定到单条断言及其所依赖的变更。

编码智能体会记住“这个函数满足某约束”之类的结论。仓库一改动，简单按文件触碰失效会过度删除；笼统让模型判断整个差异是否改变行为，又没有问到这条结论本身。本文把问题改写为某个具体主张在此次提交后是否仍成立，并用同一测试断言跨提交执行的结果构造真值。在二十三个 开源软件库中，作者收集了一万余条主张与一百八十四次执行验证的翻转。五个价格跨度很大的模型在“整段差异是否保持行为”问题上精度仅约零点二九至零点三三；直接判断具体主张时可达零点七零五至零点九七四。给整体判断器额外附上主张文本几乎没有用，改变所问的问题才带来主要提升。测试函数是清晰可执行的主张，普通自然语言记忆未必同样容易验证；但“对每条记忆单独问是否失效”是可直接借鉴的设计。

**编辑点评**：执行真值减少主观标注问题，但可执行测试与自由文字记忆存在明显差异。

**为什么值得读**：为编码智能体记忆失效机制提供比文件触碰或整段差异分类更精确的问题定义。

[阅读论文 PDF](https://arxiv.org/pdf/2609.25130)

## 评测与安全

### 任务状态该提示智能体，还是由系统强制执行

How Strongly Should Task State Influence an LLM Agent?

🌟🌟🌟

**问题**：任务状态已写在清单里，智能体为何仍会违规？

**结论**：外部门禁在状态可判定的航空政策任务提高通过率；当门禁误判情境时也会伤害表现。

**新意**：固定任务规则和模型，只改变状态信息从展示、自写、指令到强制拦截的作用强度。

长程任务常有先决条件、取消步骤和允许重做的工作。把这些状态写在提示里是一种做法，交给外部状态机阻止违规动作又是另一种。本文把两者之间的几级控制拆开比较：原始对话、准确清单、智能体自写账本、逐轮状态指令，以及依据执行回执更新并拒绝违规动作的门禁。实验显示准确清单并不必然可靠；自写账本虽可能记录不准，有时反而比被动阅读清单更有效。门禁无需模型主动服从，在航空政策任务中把大模型通过率从零点三九提高到零点五四。但如果任务取决于识别语境线索，而门禁把请求错映射到某个步骤，它会拒绝本可完成的动作，并让小模型表现下降。结论不是状态一律要强制执行，而是先判断失败是否真的能由状态机识别，并验证状态和匹配器是否准确。

**编辑点评**：配对比较厘清了因果，但门禁效果受状态真值和请求匹配准确度共同限制。

**为什么值得读**：设计长程工作流时可以用此框架判断应提示、指导还是强制拦截。

[阅读论文 PDF](https://arxiv.org/pdf/2609.25686)
