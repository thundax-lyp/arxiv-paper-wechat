### [1] CORAL：面向生产推荐系统的原生 LLM 编排框架

> **原标题：** CORAL: An LLM-Native Harness for Production Recommender Systems

- **评分：** 9/10
- **作者/机构：** 作者机构未在已核查正文中明确标注
- **关键词：** LLM、Agent

**📌 研究问题与结论**  
CORAL 把 LLM、决策记忆、数值优化器和线上 A/B 结果组成持续闭环，在固定资源约束下调整生产推荐系统的检索与服务配置。

**🔧 方法与系统**  
每轮读取运行信号和历史决策效果，LLM 通过工具提出预算可行的配置，线上测量结果写回记忆供后续更新。

**💡 核心创新**  
将 Agent 放在生产推荐系统的持续、受约束控制面，而非只用于离线建模或单次推荐。

**🏋️ 训练与数据**  
无参数更新；在两个大型社交平台表面用线上 A/B 实验评估持续配置决策。

**📊 结果与证据**  
一项实验让新低信号用户视频会话提高 0.23%；另一项在参与度无统计显著下降下，经两轮把年化容量节省较第一轮提高 44%。

**🧐 编辑点评**  
真实大规模 A/B 证据强，但系统和数据不可公开，外部团队难以复现，也需高度可靠的约束与人工治理。

**⭐ 为什么值得读**  
适合已有实验平台、强约束优化器和回滚机制的大型推荐团队；不宜直接照搬到缺少观测与治理的系统。

[arXiv 原文](https://arxiv.org/abs/2609.02730) · [PDF](https://arxiv.org/pdf/2609.02730)

### [2] Repo-To-Skill：将 GitHub 仓库蒸馏为 AI4AI 技能

> **原标题：** Repo-To-Skill: Distilling GitHub Repositories Into AI4AI Skills

- **评分：** 9/10
- **作者/机构：** 作者机构未在已核查正文中明确标注
- **关键词：** LLM、Agent

**📌 研究问题与结论**  
Repo-To-Skill 提出 DisCo：从代码仓库和论文蒸馏、验证可复用操作知识，并在 AI 研究 Agent 执行任务时按需加载 Skill。

**🔧 方法与系统**  
离线将广泛使用的 ML 仓库整理为 Skill 图和路由库，同时按具体任务生成所需的定向 Skill，并在写入前验证。

**💡 核心创新**  
把仓库中的操作知识明确建模为 Agent 的可路由、渐进加载层。

**🏋️ 训练与数据**  
构建来自 1,000 个 ML 仓库的 5,000+ Skill 库；在 MLE-bench、PaperBench、FrontierCS、PassNet 做固定设置对照。

**📊 结果与证据**  
论文报告 GPT-5.5 研究 Agent 加 Skill 后四个基准分别提高 134.3%、34.4%、9.2% 和 14.0%。

**🧐 编辑点评**  
在固定骨干与执行预算下做了有价值的有无 Skill 对照，但库的质量与可迁移性仍取决于蒸馏和验证流程本身。

**⭐ 为什么值得读**  
适合构建研究或开发 Agent 知识层的团队；需独立检查 Skill 的触发、可执行性和来源漂移。

[arXiv 原文](https://arxiv.org/abs/2609.02749) · [PDF](https://arxiv.org/pdf/2609.02749)

### [3] Loom：通过嵌入空间重加权编织自由文本诊断共识

> **原标题：** Loom: Weaving Diagnostic Strands into Free-Text Consensus via Embedding-Space Reweighting

- **评分：** 8/10
- **作者/机构：** 作者机构未在已核查正文中明确标注
- **关键词：** LLM、Agent

**📌 研究问题与结论**  
Loom 将面向故障根因分析的规则化自由文本假设嵌入向量空间，以迭代质心重加权聚合，再只用一次轻量 LLM 调用生成诊断结论。

**🔧 方法与系统**  
模块化 Diagnostic Strands 从遥测中填充假设，嵌入后按与共识中心的关系迭代重加权，最终把候选与权重交给一次 LLM 综合。

**💡 核心创新**  
把弱监督的可审计聚合扩展到开放文本假设，并将生成模型限制为最后的单次表达步骤。

**🏋️ 训练与数据**  
无模型训练；在 OpenRCA 的 Bank、两个 Market 子集和 Telecom 场景评测。

**📊 结果与证据**  
论文称在 Bank 与 Market-2 上可匹配所比较的自治代理，在 Market-1 和 Telecom 分别低 11.43 与 11.77 个百分点；全场景只需一次 LLM 调用，报告约快 26 倍。

**🧐 编辑点评**  
真实部署导向和单次调用的效率证据清晰，但能力边界由预先定义的诊断规则覆盖面与嵌入表示共同决定。

**⭐ 为什么值得读**  
适合高频、可定义诊断目录且重视延迟与可解释性的运维场景；未知故障需要人工或离线流程新增规则。

[arXiv 原文](https://arxiv.org/abs/2609.02649) · [PDF](https://arxiv.org/pdf/2609.02649)

### [4] 信念校准优化：面向智能体优化的显式世界模型

> **原标题：** Belief-Calibrated Optimization: An Explicit World Model for Agentic Optimization

- **评分：** 7/10
- **作者/机构：** Yuhan Chen、Zhihua Tian、Mahavir Dabas 等；Virginia Tech、Amazon及独立研究者。
- **关键词：** agent-optimization、persistent-beliefs、calibration

**📌 研究问题与结论**  
BCO让优化Agent显式记录修改预期、评估实际结果并修订持久信念文档，以改善围绕冻结模型的脚手架代码。

**🔧 方法与系统**  
以Markdown世界模型保存可反驳信念，修改前写预测，运行真实评估后新增/修订/合并/删除信念；优化器可读历次diff、快照和逐任务结果。

**💡 核心创新**  
把优化者对环境的隐含预期变为跨轮可维护、可被结果推翻的文档，并对其内容与单纯持久笔记做对照。

**🏋️ 训练与数据**  
不更新目标模型权重，只优化代码；覆盖LongMemEval-s、LoCoMo、GAIA、AppWorld、Terminal-Bench 2.0，固定模型与匹配迭代预算；AppWorld/TB训练任务事先筛除不稳定任务。

**📊 结果与证据**  
§4：五基准所报留出增益0.022–0.152；但换目标后AppWorld高推理档BCO有99/372任务未完成，全样本0.516低于vanilla 0.685。完整文档预测优于伪造文档，但四运行符号检验p=0.125。

**🧐 编辑点评**  
同证据面控制组及伪造内容消融支持文档内容有用，但主比较每基准每方法仅一条轨迹。两项记忆基准从三个候选的留出成绩选最好，不能称完全未用留出集选模型；自然语言信念也不是统计校准后验。

**⭐ 为什么值得读**  
适合自动优化Agent脚手架的读者，预测-观测-修正协议可借鉴，同时需关注留出选择偏差及上下文开销导致的迁移失败。

[arXiv 原文](https://arxiv.org/abs/2609.01861) · [PDF](https://arxiv.org/pdf/2609.01861)

### [5] CHIME：面向长程智能体规划的信用感知分层记忆演化

> **原标题：** CHIME: Credit-Aware Hierarchical Memory Evolution for Long-Horizon Agentic Planning

- **评分：** 7/10
- **作者/机构：** 厦门大学、浙江大学、阿里巴巴集团。
- **关键词：** agent-memory、credit-assignment、planning

**📌 研究问题与结论**  
CHIME 将规划经验和执行经验分库，在记忆写入前先判断成功或失败应归因于哪一阶段，减少把执行失误误存成规划教训。

**🔧 方法与系统**  
先相似检索再按历史归因价值重排，任务结束后输出规划、执行、两者或皆非的归因，定向奖励、惩罚、合并和裁剪对应记忆。

**💡 核心创新**  
把阶段责任归属设为记忆更新前置门，并联合管理记忆内容及其复用价值。

**🏋️ 训练与数据**  
冻结 Qwen3.5-Flash 与 DeepSeek-V4-Flash，四个 Agent 基准按 7:3 分记忆积累与冻结评估；三种任务顺序，检索 20 候选取 3 条。

**📊 结果与证据**  
§5 冻结评估均值相对最佳基线分别提高 2.96 和 3.68 个百分点；去掉归因门降 2.44 点、合并双库降 3.60 点。重跑时 56.3%–67.6% 已归因失败得到纠正，非普遍恢复保证。

**🧐 编辑点评**  
归因由同一骨干自反思完成，稳定性不等于因果正确；带生成记忆重跑后的恢复也缺少同预算无记忆重试对照来单独解释归因质量。跨骨干有效主要限于同基准，跨基准迁移较弱。

**⭐ 为什么值得读**  
适合维护跨任务 Agent 记忆的团队，可参考先诊断再入库、阶段分库与冻结记忆评测协议。

[arXiv 原文](https://arxiv.org/abs/2609.02074) · [PDF](https://arxiv.org/pdf/2609.02074) · [代码](https://github.com/ATH-MaaS/Marco-DeepResearch)

### [6] SkillGLoW：长程任务流中自我改进智能体的过程族技能整合

> **原标题：** SkillGLoW: Procedural-Family Skill Consolidation for Self-Improving Agents on Long-Horizon Task Streams

- **评分：** 7/10
- **作者/机构：** 新加坡国立大学；Institute of Advanced Intelligence and Computing（IAIC）
- **关键词：** LLM

**📌 研究问题与结论**  
SkillGLoW 将逐任务经验汇成程序族先验，运行时重新生成实例细节，并凭执行验证决定入库。

**🔧 方法与系统**  
多视角嵌入共识聚类、去实例化压缩、真实执行门禁及全局先验与局部经验组合。

**💡 核心创新**  
以共享解题程序作为复用单位，同时控制经验库膨胀和压缩后退化。

**🏋️ 训练与数据**  
三种冻结 API 模型覆盖四个基准，持续更新文本技能而非参数；检索用量化 Qwen3-Embedding-8B。

**📊 结果与证据**  
主表十二次持续运行全局先验平均提升 17.2 个百分点，库缩小 3.6 倍；60 个未见 ALFWorld 任务平均 73.9%→83.9%，30 个软件修复实例三次均值 40.0%→45.6%。

**🧐 编辑点评**  
主表每格单次运行且取多轮峰值，不能等同独立测试提升；任务流仅 20–53 项。迁移仍在同基准类别内，跨领域与跨模型尚未测试，错误聚类也会引入回归。

**⭐ 为什么值得读**  
适合研究 Skill 维护、验收与回滚，优先参考独立迁移部分。

[arXiv 原文](https://arxiv.org/abs/2609.02217) · [PDF](https://arxiv.org/pdf/2609.02217)

### [7] APEx：面向自适应深度研究问答的智能体过程经验蒸馏

> **原标题：** APEx: Distillation of Agent Procedural Experience for Adaptive Deep Research Question Answering

- **评分：** 7/10
- **作者/机构：** 作者机构未在已核查正文中明确标注
- **关键词：** LLM

**📌 研究问题与结论**  
APEx 联合训练执行、经验蒸馏和规划模块，再用技能先验约束测试时规划器学习。

**🔧 方法与系统**  
轨迹记忆与类别技能分层，三阶段交替 GRPO；在线根据回答证据和技能一致性奖励更新规划器。

**💡 核心创新**  
技能生成本身接受奖励训练，并参与测试时参数适配的约束。

**🏋️ 训练与数据**  
执行器 Qwen2.5-VL-7B，蒸馏器与规划器 Qwen3-8B，FVQA/MATPO 训练；Qwen3-32B 判分，单节点八张 A100。

**📊 结果与证据**  
七基准平均准确率 64.4，对记忆基线 MIA 61.4；移除实例记忆仅保留技能平均降 1.8 点，换执行器也有提升。

**🧐 编辑点评**  
无标准答案不等于无监督风险：三个评委角色及仲裁仍可能共享模型偏差，伪奖励还会回写记忆。与直接回答闭源模型比较同时混入工具、记忆和在线适配成本。

**⭐ 为什么值得读**  
适合研究经验蒸馏和在线学习，需增加独立奖励审计及顺序、成本控制。

### [8] PaperCompiler：通过仓库级规格编译实现忠实的论文到代码生成

> **原标题：** PaperCompiler: Faithful Paper-to-Code Generation via Repository-Level Specification Compilation

- **评分：** 7/10
- **作者/机构：** 作者机构未在已核查正文中明确标注
- **关键词：** LLM

**📌 研究问题与结论**  
PaperCompiler 把论文证据逐步编成仓库要求、文件职责和接口契约，再按依赖生成代码。

**🔧 方法与系统**  
标明证据来源和推断状态，协调要求、禁止方法降级、分配所有权并裁切每文件上下文。

**💡 核心创新**  
把论文依据和跨文件契约连接，减少自由摘要在后续代码生成中的语义损失。

**🏋️ 训练与数据**  
无需模型训练；90 篇 Paper2CodeBench 论文，o3-mini 生成、o3-mini-high 判分，九篇做消融。

**📊 结果与证据**  
参考作者仓库的 1–5 分均值由 3.647→4.152；严重评委批评占比 13.2%→6.1%。无参考评分在部分消融反而更高，说明判分协议影响结论。

**🧐 编辑点评**  
编译出的契约仍是生成指导，未提供形式保证；主要指标由同家族模型评分，不能证明仓库可运行或复现论文结果。仅文本输入也会丢失关键图示信息。

**⭐ 为什么值得读**  
适合论文复现与仓库级代码生成，执行测试和独立人工验证仍需补上。
